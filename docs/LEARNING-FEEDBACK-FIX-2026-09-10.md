# 학습 데이터와 자동 학습 로그 수정

수정본을 소스와 별도 업데이트 ZIP으로 준비했다. 실행 중인 프로그램, 개인 설정,
실거래 승인과 계좌 상태는 변경하지 않았다. 실제 공급자 데이터를 재조회하거나
실주문으로 시험하지 않았다.

## 변경

- 종목별 일봉의 시작일만 다르면 가장 늦은 시작일 이후의 실제 공통 자료를 사용한다.
- 원본 가격과 시간 검사를 먼저 수행한다. 누락 날짜를 채우거나 중간 날짜를 지워
  수익률 구간을 합치지 않는다. 내부 누락·종목 간 최신 날짜 불일치는 차단한다.
- 응답에서 빠진 요청 종목도 빈 데이터로 보존하여 조용히 학습 대상에서 빠지지 않는다.
- 차단 시 종목, 일봉 개수, 날짜 범위와 누락 날짜를 표시한다. 정상 처리 시 사용 기간과
  제외한 과거 일봉 수를 표시한다.
- 자동 학습 결과와 다음 실행 시각을 화면과 기존 로그 파일에 기록한다. 다음 주기가
  실패하면 이전 결과를 재사용하지 않는다. 아무 작업이 없는 주기도 실행 기록을 남긴다.
- 초기 데이터 검사가 차단돼도 기존 진행 상태 알림을 유지한다.

## 검증

- 새 회귀 테스트 15개 통과. 수정 전에는 입력 관련 6개 및 화면 관련 회귀 사례가 실패했다.
- 관련 검사 39개 통과, 추가 컨트롤러 회귀 검사 21개 통과.
- 최종 전체 검사: **883 passed, 17 failed, 95 subtests passed**.
- 실패 17개는 이번 변경 모듈을 수정 전 버전으로 되돌린 **별도 격리 사본**에서도 재현했다.
  원래 작업 공간은 되돌리지 않았다. 실패 영역은 Alpaca 체결 이력 7개, 주문 중복 방지
  1개, 브로커 오류 비밀값 마스킹 2개, 카나리 감사 마스킹 7개다.
- 신규 정합성 모듈의 Ruff 및 BasedPyright 진단은 0개다. 기존 runner에는 수정 전후
  동일한 AuditLogger 타입 오류 4개가 있고, 기존 모듈의 import/예외 처리 lint는 남아 있다.
- 실제 Tk DashboardApp, 결과 큐, 컨트롤러와 학습기를 격리된 파일 경로와 고정 일봉으로
  구동했다. 누락 일봉 차단 → 공통 319개 일봉으로 연구 완료 → 빈 주기 기록을 검증했다.
  화면 텍스트와 저장된 trader.log가 일치하며 모든 실제 주문 수는 0이다.
- Windows 화면 캡처 연결은 두 차례 모두 native pipe unavailable로 실패했다.
  따라서 스크린샷 기반 외형 판정은 하지 않았으며 실제 Tk 위젯 내용과 파일 출력으로
  기능을 검증했다.
- 독립 검토: 목표/제약, 코드 품질, 보안, 문서 맥락, 실제 오프라인 QA 모두 해당 범위 통과.
- PyInstaller 빌드 완료. 수정한 5개 모듈의 내장 코드가 최종 소스와 일치한다.
- 생성한 EXE의 내장 진단: 종료 0, resource_loaded=true,
  submitted_order=false, network_client_constructed=false.

## 배포 상태와 제한

업데이트: `dist/NasdaqAutoTrader-learning-feedback-update.zip`.
묶음 안의 UPDATE-NOTES.txt에 적용 방법을 적었다. 개인 설정·자격정보는 포함하지 않는다.
현재 실행 파일은 교체하거나 재시작하지 않았다.

전체 종목이 같은 오래된 마지막 날짜를 갖는 경우의 절대 최신성 검사는 이번 상대 정합성
수정 범위에 포함하지 않는다. 실제 운영 데이터의 불일치가 단순 시작일 차이인지,
보충이 필요한 실제 누락인지는 공급자 원본으로 별도 확인해야 한다. 이번 수정은 후자의
차단을 해제하지 않고 원인을 표시한다. 연구 완료가 전략 검증 통과나 LIVE 승격을 뜻하지 않는다.

재현 기록은 `.omo/evidence/learning-data-feedback/`의 full-tests-final.txt,
baseline-tests.txt, baseline-toggle.txt, native-qa-result.json, native-ui-log.txt,
binary-diagnostic.json과 build.txt에 보관했다. 임시 실행 파일 두 개는 개별 삭제하여
압축을 풀지 않은 실행 파일은 기존 dist의 한 개만 남겼다. 임시 폴더의 일괄 재귀 삭제는
자동 승인 검토에서 차단되어, 격리 사본과 빌드 자료 폴더는 유지했다.
