## 시작·중지·종료

| 작업 | 조작 / 의미 |
|---|---|
| 자동 로컬 모의 | `run_p1_trader.cmd` 더블클릭. PC가 켜져 있고 창이 실행 중일 때 자동 처리 |
| 신규 진입 중지 | `신규 진입 일시정지`. 이미 제출된 주문은 취소하지 않으며 체결 확인·보유분 일봉 보호 판단은 계속 |
| 신규 진입 재개 | `신규 진입 재개`. 놓친 진입을 강제로 복구하지 않음 |
| 상태 확인 | 현금·평가·P1 소유 보유·미결 주문·자료 시각·오류·진입 차단 이유 표시 |
| 완전 종료 | `프로그램 종료` 또는 창 닫기. 진행 중 작업 종료를 기다린 뒤 잠금 해제. 이후 보호 판단도 중단. 브로커 미체결은 남을 수 있음 |
| 다른 모드 선택 | 종료 후 `open_p1_control.cmd` 실행. 실행 중 모드 변경은 차단 |

공유 GUI 잠금, 운영 상태 잠금, KIS 계좌 주문 lease와 기존 트레이더 프로세스 확인을 사용합니다. 기존 EXE/소스 트레이더를 먼저 종료해야 합니다. 기존 패키지 EXE 내부의 잠금 호환성은 EXE를 실행하지 않아 미검증이며, 시작 전과 운영 점검 시 기존 프로세스를 발견하면 차단합니다. 잠금을 지원하지 않는 임의의 외부 프로그램·다른 PC까지 통제하지는 못합니다.

`register_p1_local_startup.cmd` / `unregister_p1_local_startup.cmd`는 사용자가 선택해 실행하는 등록·해제 도구입니다. 별도 **로컬 모의 전용** 로그온 작업만 다루며 등록 직후 실행하지 않습니다. 이번 개발에서는 등록·해제·실전 예약 작업을 실행하지 않았습니다.

짧은 PowerShell 명령이 필요하면 프로젝트 폴더에서 `./run_p1_trader.cmd`, `./open_p1_control.cmd`, `./p1_status.cmd`를 사용합니다.

## 고정한 전략과 운영 차이

원본 `experiments/p1_paper_v1/protocol.json` 및 그 65개 소스/설정 해시를 시작 시 검사합니다. 운영판 자체 소스는 `experiments/p1_operations_v1/manifest.json`으로 식별합니다. 변경 후에는 새 버전·상태로 분리해야 하며 기존 평가를 덮어쓰지 않습니다.

- 종목군: CMCSA / HIVE / KDP, 기존 사전 고정 종목군. 자동 종목 재선정·학습·P2 없음.
- P1은 기존 C 진입 점수식, 매수 점수 5, 동시 매도 점수 4 이상 차단, 완성 일봉 중복 판단 차단. 강제 매수·최소 매수 횟수·추가매수 없음.
- 청산 우선순위: **고정 손절 8% → 고정 익절 16% → 진입가 대비 +8%에서 활성화된 최고 종가 대비 4% 추적 청산 → 기존 일반 기술적 매도**. ATR 후보·시간 강제 청산은 추가하지 않음.
- 지표와 보호 판단 모두 **완성 일봉**. 처음 64봉은 준비 자료, 이후 누적 이력을 사용. 15초 상태 확인 주기가 장중 손절 판단을 뜻하지 않습니다.
- 최대 정수 수량: 실제 초기 손절 거리 + 수량별 매수/손절 매도 비용 + 불리한 체결 비용을 사용. 거래 계획 위험 2%, 보유/예약 계획 위험 합계 6%, 종목/총 투자 50%, 주문 $35, 현금 여유 5%. 0주를 1주로 올리지 않습니다.
- 보유는 확인 체결 수량/평균가와 초기 손절·최고 종가를 저장합니다. 계획 위험은 실제 손실 상한 보장이 아니며 손실을 2%로 잘라 기록하지 않습니다.

**실행 정책 차이:** 로컬 모의는 기존 다음 봉 모형을 유지하며, 수신 후에 기록되는 모의 체결입니다. KIS는 다음 정규장 개장 이후 DAY 지정가를 실제 API에 요청하도록 연결했습니다. 매수 제출 창은 개장 후 5분 이내이며, 놓친 매수는 만료 처리합니다. 접수·부분 체결·체결 이력·잔고 반영은 별도로 확인합니다. 내부 잔고 조회·인증이 끝난 뒤 실제 전송 직전에도 모의 서버·계좌 잠금·주문 내용·시간창을 재확인합니다. 또한 KIS 주문 직전에는 실제 조회된 현금·주문가능금액과 P1 평가액으로 한도를 다시 계산합니다. KIS의 당일 평가손실 2% 신규매수 중단은 뉴욕 날짜별 잔고 조회 평가액에 적용하므로 로컬 일봉 평가와 관찰 시점이 다릅니다. 이는 진입 안전 한도이며 장중 보호 매도로 바꾸는 것은 아닙니다. 이 운영 체결·위험 관찰 방식을 과거 백테스트와 동일한 결과라고 주장하지 않습니다.

거래일·휴장·단축장·DST는 기존 고정 거래 달력(2027-12-31까지)을 사용합니다. 일봉은 종가 후 5분부터 수집 대상으로 삼고, 실패 시 5분 간격으로 재시도합니다. 가격은 기존 Yahoo 수집기, 환율은 ECB 수집기를 사용합니다. 데이터 발생/수신/판단 시각을 구분하며 과거 빈 구간은 준비 자료로만 보완합니다. 데이터 누락·수정·분할·시계 역행은 신규 진입 차단 사유입니다.

## KIS 모의 연결 준비

`experiments/p1_operations_v1/kis-paper.env.example`을 위 운영 폴더의 `kis-paper.env`로 복사하고 **전용 모의투자** `KIS_PAPER_APP_KEY`, `KIS_PAPER_APP_SECRET`, `KIS_PAPER_ACCOUNT_NO`를 사용자가 입력합니다. 일반 `KIS_APP_*` 또는 기존 `.env`의 실전 키로 자동 대체하지 않습니다. 이 파일·토큰·운영 장부를 Git에 넣지 마세요.

`open_p1_control.cmd` → `kis_paper` → `선택 모드 시작`. 인증·API 지원 오류가 나면 로컬 모의와 구분해 표시합니다. 현 계좌의 기존 보유를 인수하지 않으며 해당 종목 신규 매수도 차단합니다. 외부 주문/보유 변동, 불명확한 응답, 체결 이력과 잔고 불일치가 있으면 무조건 재주문하지 않습니다. DAY 주문이 미체결 목록에서 사라졌다는 사실만으로 종료되었다고 가정하지 않습니다. 응답에서 주문번호를 받지 못한 제출은 시각·종목·수량이 같은 이력이 하나 있더라도 자동으로 P1 소유라고 인수하지 않습니다. 이력이 불명확하면 신규 진입 차단을 유지하고 증권사 확인 및 명시적 주문 소유권 대사가 필요합니다.

공식 예제에는 해외주식 모의 주문, 미체결/체결 조회 경로와 미국 모의 지정가(00) 지원이 나옵니다. 서버에서 이 계좌로 되는지는 미확인입니다. 미국 모의 매도 TR ID 설명과 예제 실행 코드에는 차이가 있어 현재 구현의 `VTTT1006U`를 서버 검증 없이 바꾸지 않았습니다. [KIS 공식 주문 예제](https://github.com/koreainvestment/open-trading-api/blob/main/examples_llm/overseas_stock/order/order.py), [공식 미체결 조회 예제](https://github.com/koreainvestment/open-trading-api/blob/main/examples_llm/overseas_stock/inquire_nccs/inquire_nccs.py), [공식 체결 조회 예제](https://github.com/koreainvestment/open-trading-api/blob/main/examples_llm/overseas_stock/inquire_ccnl/inquire_ccnl.py).

## 비용과 실전 승인

로컬 기본: 매수/매도 각각 0.25%, 최소 $0, 스프레드 10bp·슬리피지 10bp. 확대 조건은 수수료를 유지하고 스프레드/슬리피지 각각 30bp. 편도 가격 영향은 각각 15bp/45bp입니다. **실제 계좌 비용이 확인된 값이 아닙니다.** KIS 체결가는 확인된 이력 값을 쓰며 수수료는 추정치로 따로 표시합니다. 가상의 가격 충격을 실제 체결가에 다시 차감하지 않습니다. 실계좌 수수료·기타 세금·시장 충격의 정확한 재현은 미검증입니다. USD 거래 때마다 환전 비용을 반복 차감하지 않습니다.

`실전 검토 / 요청` 화면에서 계좌, 실행 경로/버전, 종목/조건, 한도, 배정액, 손실 중단, 기존 보유 제외, 비용/운영/수익성 미검증을 확인합니다. 계좌·배정액·손실 중단과 명시적 문구를 저장해도 **요청 기록일 뿐 주문 승인 아님**입니다.

남은 승인 차단은 `p1_live_strategy_approval_binding_unavailable`와 `live_session_authorization_required`입니다. 기존 승인 체계는 승인된 학습 전략/종목/위험/브로커에 결합되어 있어 P1이 그 신분을 빌릴 수 없습니다. P1에 정당하게 적용되는 기존 승인 자료·결합 및 계좌/거래일 실전 세션 승인이 필요합니다. 현재 화면에서 플래그를 켜거나 동의를 저장하는 것만으로 실전 시작을 허용하지 않습니다. 60거래일 평가 완료를 운영 기능 개발의 선행조건으로 삼지는 않았습니다.

## 검증과 복귀

변경 경로 테스트는 `python -B scripts/run_offline_tests.py -q -p no:cacheprovider tests/test_p1_ops_runtime.py tests/test_p1_ops_gui.py tests/test_p1_ops_broker.py tests/test_p1_ops_broker_safety.py tests/test_p1_ops_broker_recovery.py tests/test_p1_ops_broker_clock.py tests/test_p1_ops_broker_balances.py tests/test_p1_ops_kis.py`로 재현합니다. 실제 Tk 화면 테스트와 캡처, 접수/부분 체결/거부/불명확 응답/잔고 지연/재시작·중복·잠금·저장 실패를 격리 환경에서 확인합니다. 서버 인증·호가/거래량 기반 실체결·장기간 운용·수익성은 아직 확인하지 못했습니다.

복귀는 P1 운영 창을 완전히 닫고 기존 `run_trader_gui.ps1` 또는 원래 사용하던 EXE를 실행합니다. 기존 EXE·실거래 설정·실제 보유 정책은 변경하지 않았습니다. 선택적으로 등록한 P1 자동 시작이 있다면 위 전용 해제 파일을 먼저 실행하세요. 실제 브로커 주문이 남아 있다면 종료만으로 취소되는 것은 아닙니다.
