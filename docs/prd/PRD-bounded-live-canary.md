# PRD: 장중 한정 소액 실거래 카나리

**Version**: 0.1
**Date**: 2026-07-17
**Status**: Implemented and production-reviewed
**Size**: L

## 1. Problem Statement

검증된 CHAMPION 전략이 없어 기존 무인 자동매매는 의도대로 실주문을 차단한다. 운영자는 그 안전장치를 제거하지 않으면서도 오늘 미국 정규장 동안 소액 실계좌로 주문·체결·청산·복구 경로를 무인 검증하고 데이터를 축적하려 한다. 기존 `day-test`는 매수 1회 이후 청산을 자동 관리하지 않고, KIS 어댑터에는 미체결 조회와 취소가 없어 그대로는 장시간 무인 운용에 적합하지 않다.

## 2. Goals & Non-Goals

### Goals

- 오늘 시장일에만 유효한 별도 승인을 통해 실거래 카나리를 실행한다.
- 주문당 최대 20 USD, 1주, 동시 1포지션, 하루 최대 3회 왕복을 강제한다.
- 진입 후 +5% 또는 -5% 도달, 또는 장 마감 15분 전이면 청산을 시도한다.
- 정규장 전후에도 프로세스는 안전하게 대기·종료하고 장중에는 15초 가격 감시, 60초 포지션 확인과 15분 후보 스캔으로 데이터를 기록한다.
- 모든 주문을 미체결 조회, 포지션 조회, 취소와 내구성 상태로 조정해 재시작 중복 주문을 막는다.
- 기존 CHAMPION 자동매매 경로와 승인 정책은 변경하지 않는다.

### Non-Goals

- 수익성 또는 정확히 ±5% 가격에서의 체결을 보장하지 않는다.
- 카나리 결과를 CHAMPION으로 자동 승격하지 않는다.
- 신용·마진·공매도·분할주·장전·장후 주문을 허용하지 않는다.
- 나스닥 전 종목을 매 주기 개별 조회하지 않는다. 검증된 정적 유니버스와 KIS 거래량 상위 30개를 1차 검토하고, 19.50 USD 이하 상위 최대 10개만 호가·상세 조회한다.
- 개발·테스트·빌드 중 실주문을 제출하지 않는다.

## 3. User Stories & Acceptance Criteria

### US-1: 하루 한정 무인 실거래

- 실행 파일 해시, 계좌 지문, 시장일, 고정 위험값에 바인딩된 승인 파일이 없거나 만료되면 신규 매수 주문 0건으로 종료한다. 이미 확인된 카나리 소유 포지션에는 별도의 exit-only 상태만 적용할 수 있다.
- 설정 `mode=live`, `allow_live_trading=true`, 환경 승인 `YES`, KIS 실전계좌가 모두 확인돼야 한다.
- 계좌 지문은 `SHA-256("kis-real|" + account_no + "|" + account_product_code)`로 만들고, 승인 생성과 매 실행 시 실제 인증된 자격증명의 지문·실전 base URL·상품코드가 모두 일치해야 한다.
- 승인은 현재 대화에서 승인받은 운영자가 전용 CLI에 시장일이 포함된 정확한 확인 문구를 직접 전달할 때만 원자적으로 발급한다. 감시 작업과 자동 시작 경로에는 승인 생성 명령을 포함하지 않는다.
- 시작 시 계좌에 기존 포지션 또는 미체결 주문이 하나라도 있으면 신규 진입을 차단한다.

### US-2: 현금 한도와 주문 소유권

- 매수 직전에 예수금과 종목별 주문가능금액을 새로 조회하며 둘 중 작은 값이 수수료 버퍼 포함 주문금액보다 커야 한다.
- 매수는 1주이며 주문가격과 버퍼를 합쳐 20 USD를 넘을 수 없다.
- 카나리가 기록한 주문번호와 종목만 관리하고, 외부 포지션·주문이 나타나면 신규 주문을 영구 차단한다.
- 매도 수량은 카나리 소유 포지션 1주를 넘을 수 없다.

### US-3: 체결 조정과 장애 복구

- 주문 접수 후 포지션과 미체결을 함께 조회한다.
- 1주 포지션이 생기면 체결, 같은 주문번호가 미체결이면 대기, 둘 다 아니면 주문체결내역으로 최종 상태를 확인한다.
- 매수 미체결은 제한시간 뒤 취소하고 취소 확인 전에는 다른 주문을 내지 않는다.
- POST 연결 종료처럼 결과가 불명확하면 같은 주문을 재전송하지 않고 조정 전용 상태로 전환한다.
- 프로세스 재시작은 원자 상태 파일과 전용 프로세스 잠금을 사용해 같은 일일 예산과 주문을 이어받는다.
- 1주 주문이므로 부분 체결은 0주 또는 1주로만 해석한다. 그 외 수량은 소유권 불일치로 차단한다.
- POST 응답에서 KIS 주문번호를 받지 못하면 어떤 시각·가격·종목 유사성으로도 주문을 소유한 것으로 추정하지 않는다. 즉시 영구 `manual_reconciliation_required`로 전환해 신규 주문, 자동 취소와 해당 결과로 생긴 미확인 포지션의 자동 청산을 금지한다. 주문번호가 확인된 주문만 exact ID로 조정한다.
- 결과 불명 상태는 장 마감 뒤 30분까지 15초 간격으로 조정하고, GET이 연속 실패해도 주문은 추가하지 않는다. 이후에도 불명확하면 영구 `reconciliation_required`로 남겨 다음 실행의 모든 신규 진입을 차단한다.

### US-4: 장중 데이터 수집과 청산

- 개장 15분 후부터 마감 30분 전까지만 신규 진입한다.
- 보유 중에는 15초마다 가격·손익·트리거 결정을 기록하고, 포지션은 60초마다 확인하며 호가는 트리거 또는 주문 직전에만 조회한다.
- +5%, -5%, 마감 15분 전 중 먼저 발생한 조건으로 시장성 지정가 매도를 시도한다.
- 청산 주문이 미체결이면 취소 확인 후에만 더 시장성 있는 지정가로 최대 3회 시도한다.
- 마감까지 청산 확인이 안 되면 `position_remains`를 기록하고 신규 진입을 영구 차단한다. 확인된 매수 주문과 1주 체결에서만 `EXIT_ONLY(symbol, max_qty=1, account_fingerprint)` 상태를 만들며, 승인 만료 뒤 broker lease의 허용 방향을 `sell`로 축소한다. 이 상태는 같은 종목·계좌의 보유량을 줄이는 주문만 허용하고 다음 정규장에 청산을 재개하며 절대 매수를 허용하지 않는다.
- 3회 왕복 이후에도 마감까지 무주문 후보 스캔과 데이터를 기록한다.

## 4. Technical Design

패키지 EXE의 CLI 모드로 `live-canary`와 `live-canary-arm`을 추가한다. GUI 무인 프로세스와는 별도 역할이지만 동일 실행 파일을 사용한다. 카나리는 `%LOCALAPPDATA%\NasdaqAutoTrader\runtime\live-canary.lock`과 계좌별 `broker-live-owner.lock`을 전체 수명 동안 보유한다. 모든 KIS 실주문 제출 경로는 계좌별 broker lease를 통과해야 하며, 카나리 lease가 활성화된 동안 토큰이 없는 GUI·기존 자동매매·수동 CLI 주문은 제출 전에 차단된다. 현재 GUI 설정도 드라이런으로 유지한다.

전용 Windows 작업은 5분 감시 스크립트를 통해 `live-canary` 역할만 탐지하고 재시작한다. 기존 GUI 감시 스크립트는 카나리 명령줄을 GUI 인스턴스로 오인하지 않는다.

상태는 계좌 지문 디렉터리의 `live-canary-YYYY-MM-DD.json`에 원자 교체로 저장한다. 최소 상태는 승인 nonce, 단계, 소유 종목, 진입가, 매수/매도 주문번호, 주문 시각, 왕복 수, 총 제출 수, 조정 필요 여부와 마지막 결정이다. 승인 nonce는 최초 활성화 때 상태에 기록되어 다른 상태 파일에 재사용할 수 없다. 감사 데이터는 JSONL로 저장하되 계좌번호, 키, 토큰과 원시 브로커 응답은 기록하지 않는다.

KIS 어댑터에는 공식 API에 맞춰 다음 기능을 추가한다.

- `inquire-nccs` (`TTTS3018R`): 미체결 목록
- `inquire-ccnl` (`TTTS3035R`): 당일 주문·체결 내역
- `order-rvsecncl` (`TTTT1004U`): 원주문 취소

잔고, 미체결, 체결내역은 응답의 continuation key와 `tr_cont`를 따라 최대 10페이지까지 모두 읽는다. key 반복, 페이지 초과, 페이지 일부 오류는 빈 결과로 간주하지 않고 사전점검 전체를 차단한다.

응답은 API 경계에서 타입으로 파싱하며 필수 식별자나 수량이 모호하면 실패 폐쇄한다.

## 5. Fixed Risk Policy

| Control | Value |
|---|---:|
| Maximum buy principal | 19.50 USD limit price |
| Reserved fee buffer | 0.50 USD; total cash gate 20 USD |
| Quantity | 1 whole share |
| Concurrent positions | 1 |
| Maximum round trips | 3 per market date |
| Maximum entry order attempts | 3 per market date |
| Maximum exit attempts | 3 per market session for an owned position |
| Take-profit trigger | +5% from confirmed average entry |
| Stop-loss trigger | -5% from confirmed average entry |
| Entry scan interval | 15 minutes |
| Price / position poll interval | 15 seconds / 60 seconds |
| Entry window | open +15 min through close -30 min |
| Forced exit start | close -15 min |
| Cooldown after exit | 30 minutes |

설정이나 CLI로 위 한도를 느슨하게 만들 수 없다. 더 작은 한도만 허용한다. 통화가 USD가 아니면 차단하며, 제출 직전 같은 지정가로 예수금·주문가능금액을 다시 확인한다. 지정가 체결가는 19.50 USD를 넘을 수 없다.

`EXIT_ONLY`로 다음 시장일에 넘어간 소유 포지션은 새 시장일마다 매도 시도 예산 3회를 다시 받지만 매수·종목변경·수량증가는 계속 금지된다. 이 예외는 기존 노출을 줄이는 방향에만 적용한다.

## 6. Edge Cases

| Scenario | Expected behavior |
|---|---|
| KIS GET 일시 장애 | 제한된 GET 재시도 후 무주문 대기; 조정 중이면 최대 장후 30분까지 조회만 지속 |
| 주문 POST 응답 단절 | 재주문 금지, 미체결·포지션·체결내역 조정 |
| 취소 POST 응답 단절 | 다른 주문 금지, 조회만 반복 |
| 예상 외 포지션/미체결 | 신규 진입 차단, 소유 주문만 안전 조정 |
| 상태 파일 손상 | 주문 0건, 수동 조정 필요 상태 |
| 두 프로세스 동시 시작 | 한 프로세스만 역할 잠금 획득 |
| 재시작 후 포지션 존재 | 저장된 주문 소유권 일치 시 감시 재개, 아니면 차단 |
| 가격 급변·갭 | 트리거 후 지정가 청산 시도; ±5% 체결 보장 없음 |
| 장 마감 청산 실패 | 고우선순위 로컬 경보와 운영 인계 파일을 남기고 다음 정규장 exit-only 복구 |

## 7. Security & Observability

승인 파일에는 계좌번호 대신 SHA-256 지문, 실행 파일 SHA-256, 위험정책 digest, Windows 사용자 SID의 SHA-256, 무작위 nonce, 발급·만료 시각을 포함한다. 실행 파일, 사용자, 계좌, 정책 또는 시장일이 바뀌면 재승인이 필요하다. 승인·상태·감사·`.env`가 있는 앱 데이터 디렉터리는 설치 시 현재 사용자와 SYSTEM만 접근하도록 ACL을 제한하고 ACL 적용 실패 시 카나리 설치·승인을 차단한다. 승인 파일은 임시 파일 fsync 후 원자 교체하며 감시 작업은 생성·갱신할 수 없다. 원시 주문 응답은 상태 저장소에 쓰지 않고 주문번호·정규화 상태만 보존한다. 감사 이벤트와 crash 보고에는 시각, 단계, 종목, 방향, 수량, 제한가격, 사유, 왕복 수만 허용한다.

## 8. Resource Budgets

- 후보 스캔은 15분당 1회, 거래량 순위 1회와 상세/호가 최대 20회로 제한한다.
- 보유 중 가격은 15초, 포지션은 60초, 계좌 현금은 5분 간격으로 갱신하며 주문 직전에는 모두 강제 갱신한다.
- 주문 조정 중 미체결·포지션은 15초마다 확인하되 한 tick의 전체 GET deadline은 10초다. 각 GET timeout은 `min(8초, tick 잔여시간)`이고 backoff도 같은 deadline에 포함되며, 잔여시간이 없으면 두 번째 시도를 시작하지 않는다.
- 카나리 KIS client의 단일 GET timeout은 최대 8초다. GET은 최대 2회 재시도하고 0.5~2초 bounded backoff와 주입 가능한 jitter를 사용한다. 스캔은 120초 wall budget을 넘기면 남은 종목을 건너뛰며, POST는 재시도하지 않는다.
- continuation은 endpoint당 최대 10페이지다. 가격 감시는 15초마다 price-detail 1회만 사용하고 호가는 트리거·주문 직전에만 조회한다. 모든 조회는 시장일당 6,000회의 내구성 예산에 포함하며, 다중 페이지 조회는 호출 전에 최대 페이지 수를 보수적으로 예약한다. 이 예산은 최장 보유 구간의 가격·포지션 폴링과 최대 주문 조정 예약량을 합산한 최소 필요량 이상이어야 한다. 예산이 부족하면 신규 진입과 조회를 실패 폐쇄하고 저장된 소유 포지션 상태를 보존한다.
- 감사 JSONL은 시장일당 10 MiB, 30일 보존으로 순환한다. 스캔 자료는 기록 후 메모리에서 폐기한다.

## 9. Testing Strategy

- 단위: 위험값 파싱, 진입·청산 트리거, 상태 전이, 승인 만료·해시 불일치.
- HTTP 경계 통합: KIS 미체결·체결·취소 요청과 응답 파싱, 오류·빈 응답·대소문자 필드.
- 상태 통합: 잠금 경쟁, POST 전/후 중단, 원자 저장, 손상 파일.
- 상태 장애주입: write/fsync/replace 실패, schema 손상, intent-before-POST 순서, 허용필드 redaction.
- 재시작 매트릭스: POST 전 intent, ambiguous buy POST, pending buy, cancel intent, ambiguous cancel POST, pending/ambiguous exit, 장후 조정 만료, 다음 장 exit-only 각각에서 중복 POST와 신규 진입이 0건임을 검증한다.
- 자원: page/retry/tick/session GET 예산, backoff, 로그 크기·보존과 최대 10개 상세조회 제한을 검증한다.
- CLI E2E: 드라이런 fixture로 개장 전 대기, 매수 체결, +5% 청산, 미체결 취소, 재시작 복구, 마감 종료.
- 설치본 E2E: 실제 EXE의 `live-canary-preflight`가 구성하는 거래 API 전송 계층은 잔고·보유종목·미체결 allowlist에 한해 GET만 허용하고 주문 메서드를 노출하지 않는다. OAuth 토큰 획득은 캐시가 없거나 만료된 경우 POST일 수 있으며, 이는 주문 POST가 아니다. 실제 계좌에서는 안전 boolean/count와 `submitted_order=false`만 출력하며 주문 POST가 구성되면 테스트를 즉시 실패시킨다. 개발 검증에서는 실주문 금지.

## 10. Rollout / Rollback

전체 테스트, 설치본 E2E, 다중 관점 리뷰가 모두 통과한 뒤 설치 EXE로 오늘 시장일 승인 파일을 만든다. 별도 카나리 작업을 등록·시작한다. 롤백은 신규 진입을 먼저 차단하고 카나리 소유 미체결과 포지션을 읽기 전용 조회한다. 둘 다 없을 때만 작업 비활성화, 승인 파일 삭제, 프로세스 종료를 완료한다. 잔존 상태가 있으면 exit-only 인계를 유지하며 기존 GUI·CHAMPION 경로에는 주문 권한을 주지 않는다.

## 11. BOOMER-6 Structural Check

1. **Boundary**: 기존 CHAMPION 경로와 분리된 하루 한정 역할이다.
2. **Ownership**: 계좌 지문, broker 전역 lease, 주문번호·상태 파일로 카나리 소유 주문만 관리한다.
3. **Ordering**: 의도 저장 → POST 1회 → 조회 조정 → 취소 확인 순서를 강제한다.
4. **Mutation**: 모든 위험 카운터와 단계는 원자 상태 저장소에서만 변경한다.
5. **Error**: GET 장애는 대기, POST 불명은 조정 전용, 상태 손상은 완전 차단한다.
6. **Recovery**: 프로세스 잠금과 내구성 상태로 재시작해 중복 주문 없이 이어간다.
