# PRD: 실거래 실행 경로 정리 및 분석 계산 정정

Version: 1.0 | Date: 2026-09-08 | Size: L | Status: Complete for scoped source/build/no-order verification; LIVE activation excluded

## 1. Problem Statement

실전 운용을 원하는 사용자의 요청에 따라 저장소 실행·연구·배포 경로와 GS Quant를 조사했다. 기존 테스트 기준은 623 passed, 95 subtests passed였다. 확인된 결함은 고정 수량 매수의 위험 한도 우회, 전략 판단과 무관한 최소 강제 매수, 근거 없는 TradingAgents 신뢰도, CAGR/Sortino 대체값과 날짜를 정렬하지 않은 beta이다. 테스트 통과 자체는 수익성이나 실계좌 준비 상태를 뜻하지 않는다.

## 2. Goals & Non-Goals

목표: 모든 매수 크기에서 같은 위험 상한 적용, 강제 진입 제거, 검증되지 않은 AI 분석의 주문 생성 방지, 시간 기준이 명시된 성과 계산, 배포본의 무주문 실행 검증.

비목표: 수익 보장, 신규 전략의 수익성 인증, 승인·현금 한도 완화, 실제 주문 제출, 사용자 보유분 청산, GS 유료 데이터 접근권 우회, 사용하지 않는 SDK 전체 복사.

## 3. User Stories & Acceptance Criteria

- US1: 고정 주수와 금액 주문 모두 비중·현금 여유·주문금액·ATR 위험 상한을 넘지 않는다. 고정 수량이 한도를 넘으면 거절한다.
- US2: `no_trade`를 강제 매수로 바꾸지 않는다. 보호 목적 매도와 정상 전략 주문의 권한 검사는 유지한다.
- US3: 신뢰도 없는 TradingAgents 분석은 실제 주문으로 변환되지 않는다. 후보 연구는 수동 실거래 승인과 구분한다.
- US4: CAGR, Sharpe, Sortino, 낙폭과 beta는 정의·시간·정렬 규약을 따른다. 모르는 주기를 일봉으로 가정하지 않는다.
- US5: 새 실행 파일에서 도움말, 잘못된 입력, 네트워크 없는 진단을 검증하고 실주문 없이 계좌 연결 상태를 확인한다.

## 4. Technical Design

기존 브로커 → 엔진 → 위험 관리자 → 주문 가드 → 승인·중복 방지·감사 흐름은 유지한다. 주문 생성 우회 경로를 제거하고 통계 계산은 소비자가 있는 표준 라이브러리 기반 모듈로 통합한다. `self_improvement`의 실체는 후보 평가 파이프라인이며 외부 호환 이름은 필요한 경우 얇은 별칭으로만 남긴다. 저장된 설정·전략·승인 파일을 자동으로 바꾸지 않는다. 네트워크 API 추가 없음.

## 5. Edge Cases & Error Handling

고정 수량 초과, NaN/무한대, 비정상 보유 평가액, 최소 금액보다 작은 정상 고정 주문, 신뢰도 임계값 0, 날짜 누락·주간/분봉·동일 시점 청산, 수익/변동 없는 곡선을 각각 회귀 검증한다. 불충분한 입력은 거래 가능성의 증거로 취급하지 않는다.

주기 검증은 백테스트 입력과 통계 연환산 계약에 적용한다. 기존 무주문 fixture 진단을 일봉 전용으로 바꾸는 요구사항은 아니다. 진단에서 종목이 선택되더라도 실제 거래 자격·성과 검증을 뜻하지 않는다.

## 6. Security & Permissions

기존 LIVE 승인, 시장 시간, 손실 제한, 주문 대사, 계좌 잠금 및 POST 비재시도 정책 유지. 키·토큰·계좌번호를 문서나 빌드에 포함하지 않는다. 코드 변경은 기존 코드 해시 기반 승인을 재사용할 수 있다는 뜻이 아니다.

## 7. Performance & Monitoring

통계 연산에 새 네트워크 호출을 만들지 않는다. 주문 차단 사유와 기존 감사 로그를 보존한다. 전체 테스트 및 실행 파일 진단 시간은 검증 보고서에 실제 측정값으로 남긴다.

## 8. Testing Strategy

각 결함의 실패 테스트 → 최소 수정 → 관련 회귀 테스트. 통합 후 `python -m pytest -q --disable-warnings`, 문법 검사, 격리 PyInstaller 빌드, 실행 파일 CLI 진단, 5개 관점 독립 리뷰. 실제 거래 없이 조회 전용 브로커 표면만 사용한다.

## 9. Rollout Plan

새 폴더에 빌드하고 배포 개인정보 감사를 수행한다. 실행 중인 이전 EXE 및 개인 설정은 덮어쓰지 않는다. 사용자 기존 버전은 복구용으로 유지한다. 업데이트 후 승인/전략 게이트를 다시 확인해야 한다.

## 10. Dependencies & Risks

GS Quant 고정 스냅샷 `a1427df06d55abdf9368c9766a68f1cadc713d5f`의 오프라인 수학을 참고한다. 기관 인증 API와 전체 pandas 기반 의존성은 이식하지 않는다. 기존 테스트 중 강제 매수나 상한 우회를 성공으로 기대하는 사례는 폐기된 요구사항을 명시하고 새 차단 회귀로 교체한다. 일반 안전 테스트는 약화하지 않는다.

## 11. Success Metrics

회귀 테스트·빌드·무주문 진단 성공, 강제 매수 경로 0개, 고정 신뢰도 주문 0개. 실거래 이익은 완료 기준으로 주장하지 않는다.

## 12. Open Questions

사용자의 운용 자금·일일 최대 손실 금액은 미제공. 기존 한도를 보존한다. 2026-09-08 조회 전용 카나리 사전점검은 `existing_position`, `cash_below_canary_gate`로 차단되었으며 주문은 제출하지 않았다. 카나리 준비 여부는 일반 전략 LIVE 자격과 별개이다.
