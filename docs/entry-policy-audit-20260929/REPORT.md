# 강제 진입과 약 5분 뒤 일반 매도: 후속 감사 결과

2026-09-29. 현재 로컬 코드·저장 설정·로그·배포 파일을 대조하고, 실제 조회 자료와 격리된 모의 체결로 검증했다. **최소 매수 예외가 낮은 매수 점수를 우회하는 경로는 현재도 있다. 이를 끄고 신호 충돌·동일 봉 재사용을 막는 별도 실험 정책을 구현했다. 수익 개선은 일관되게 입증되지 않았다.** 운영 설정·현재 보유 정책·EXE에는 적용하지 않았다.

## 1. 실제 실행본과 수정된 로컬 코드의 차이

감사 시 실행 중인 대상 프로그램은 발견되지 않았고 두 예약 작업은 Disabled였다. 새로 프로그램을 실행해 버전을 확인하지 않았다. 따라서 현재 작동 중인 프로세스 버전을 확정할 수 없다.

| 구분 | 확인된 사실 |
|---|---|
| 문제 기록 당시 | 2026-09-23·24·25에 `daily_minimum_best_affordable` 매수 판단과 약 5분 뒤 일반 기술적 매도 제출 기록이 있다. 제출 시각이며 실제 체결 보유시간은 아니다 |
| `run_trader_gui.ps1` 소스 실행 | 루트 `trading_config.json`: dry_run=true, live=false, minimum 필드 없음→false. 이 PS1에는 `--trading-config` 인자가 없다. `gui_launcher`의 LocalAppData 기본 인수 경로와 구분한다 |
| 설치 GUI·배포본 | `%LOCALAPPDATA%/NasdaqAutoTrader/trading_config.json`: minimum=true, live=true, dry_run=false. `dist/NasdaqAutoTrader/config.kis.json`을 GUI 설정이 덮어쓴다 |
| 현재 배포 EXE | SHA-256 `b34486f790bc45d0f6e73189999f197760c77da482c20dd1a14b94d768617cea`. 정적 bytecode 검사에서 최소 매수와 GUI 퍼센트 매핑 확인 |
| 이번 소스 변경 | 새 오프라인 진입 정책·자료 조회·비교 모듈, 공통 백테스터의 선택적 체결 시 총 비중 검사. 운영 엔진 진입 정책은 바꾸지 않음 |

9/23 제출은 현재 EXE 작성 시각보다 앞선다. 기존 배포 기록의 F198…4E97과 부합하지만 당시 이벤트에 binary hash가 없어 확정 귀속할 수 없다. 9/24·25는 B344…7CEA 재배포·재시작 이후이며 같은 한계가 있다. 이전 작업에서 바꾼 `strategy.py`와 `engine_cycle.py`도 현재 EXE와 다르므로 소스 오류 수정이 이미 배포되었다고 볼 수 없다.

현재 설치 GUI 경로의 저장 손절 **3.0%는 `config_runtime.apply_settings_to_app_config()`의 /100으로 0.03**이 된다. ATR14×3은 별도로 남는다. 당시 주문별 최종 설정 snapshot은 없어 과거 메모리 값을 완전히 증명할 수 없다. 문제의 세 기록에 남은 매도 사유는 일반 기술적 신호이며 고정 5% 손절 때문이라고 볼 증거는 없다.

경로·시각·설정 덮어쓰기·소스 줄·전체 해시: [runtime-audit.md](runtime-audit.md).

## 2. 강제 매수는 현재도 살아 있는가

**그렇다. `daily_minimum_buy_enabled`가 true일 때 실행되는 별도 예외다.** 폐기된 `daily_forced_order_enabled`와 다르다. README:9는 기본 no_trade와 minimum 예외를 함께 설명하고, README:863의 제거 대상은 daily_forced다. 과거 기능을 비교 목적으로 복구하지 않았다.

실행 경로는 `engine_automatic_cycle.py:71`의 `daily_buy_due()` → `automatic_entry_eligibility.py:78` → `daily_buy_objective.py:96`의 `daily_minimum_decision()` → `engine_cycle.py:108`이다. 충분한 봉·유효 가격·위험거리를 가진 HOLD를 BUY로 바꾸며 매수 점수 부족 또는 동시 매도 점수를 거부하지 않는다. 실제 최소 매수 경로는 위험 한도를 1%에서 **5%로 덮어쓰고** 학습 후보 선정에도 예외를 적용한다(`automatic_selection.py:117`, `engine_cycle.py:149`).

실제 `TradingEngine.run_once()`를 메모리 브로커로 실행한 회귀에서 **매수 점수 0 → 최소 매수 판단 → 5분 뒤 보유 상태에서 동일 지표의 일반 매도**를 재현했다. 다음 보유 상태는 테스트에서 명시적으로 주입했으며 실제 체결을 가장하지 않았다. 주문·취소 메서드는 호출 시 실패하도록 했다. 최소 매수 비활성화 시 0건 매수와 no_trade를 유지했고 폐기 플래그·0/1종목 보유 조건으로 우회되지 않았다.

일반 엔진에서 최소 2종목·현금 소진을 위한 다른 강제 매수 경로는 발견하지 못했다. HIVE 전용 매도 모니터와 독립 AI quant 엔진을 이 결론에 섞지 않았다. 근거와 테스트: [policy-implementation.md](policy-implementation.md).

## 3. 별도 실험 프로필에서 바꾼 것

[`experiments/entry_policy/profile.json`](../../experiments/entry_policy/profile.json)은 `dry_run=true`, `broker=offline_csv`다. GUI·운영 엔진이 선택하지 않는다.

| 정책 | 차이 |
|---|---|
| A | 현재 최소 매수의 HOLD→BUY 승격을 오프라인에서 제한적으로 재현 |
| B | A에서 최소 매수만 제거. 오늘 매수가 0건이어도 정상 no_trade |
| C | B + 동일 데이터의 매도 점수 ≥4이면 신규 진입 차단 + 더 늦게 완성된 봉에서만 일반 신호 재사용 |

양방향 점수, 평가 시각, 완성봉 ID, 데이터 지문, 기본/최종 판단, 강제 여부, 판단가·보호 mark를 남긴다. C는 같은 봉의 수정·재조회·오래된 봉으로 재진입하지 않는다. 보호 판단은 일반 신호 제한보다 먼저 실행하므로 **새로운 유효 가격의 하드 손절을 막지 않는다.** 최소 하루 보유·손실 매도 금지·주문이 없을 때 기준 완화는 넣지 않았다. 다음 완성 봉이 일반 신호 제한의 해제 조건이다.

손절 3%, 익절 5%, 트레일링 2% 활성/1% 하락, 일봉 ATR14×3/×5, 정수 1주·$35 상한, 종목당/총 투자 50%, 현금 여유 5%, 일일 손실 2% 시 신규 매수 중단을 공통으로 유지했다. **A/B/C 모두 통상 거래당 위험 1%를 썼으므로 A는 당시 전체 운용의 정확한 복원이 아니다.** 당시 최소 매수 5% 예외·학습 순위를 포함하지 않는 동일 위험 기준선이다. 실제 5% 예외의 재현은 위 엔진 회귀에서만 확인했다. 일봉 및 분봉 시장 비교는 둘 다 1%다.

초기 보호와 위험거리도 공통 legacy 계산을 유지했다. `max(고정 거리, ATR 거리)`는 보수적 수량 계산 거리이지 먼저 발동하는 실효 손절선과 같다는 뜻이 아니다. 이전 8%·10%·진입 ATR 실험은 보존하고 이번 결과와 분리했다.

독립 검토에서 백테스터의 총 투자 50%가 주문 제출 시에만 검사되는 경계를 발견해 체결 직전에도 선택적으로 검사하도록 수정했다. 기존 호출의 기본값은 None이며 새 비교만 0.5를 지정한다. 운영 위험 한도 변경이 아니다. 기존 실제 자료 산출물의 최대 체결 비중은 6% 미만이라 결과에 영향이 없음을 독립 대사했다. [fill-exposure-fix.md](fill-exposure-fix.md), [review-code.md](review-code.md).

## 5. 같은 엔진의 A/B/C 결과와 수익 개선 여부

아래는 **실제 시세에 가정한 비용을 적용한 모의 체결**이며 개인 계좌 실적이 아니다. 미실현 손익을 포함한다. 기본 비용은 편도 0.25%, 최소 $0 가정, 스프레드 10bp·추가 슬리피지 10bp다. 실제 수수료가 0이거나 이 요율이라고 확인한 것은 아니다.

| 평가 | A USD 순수익률 / 완결 거래 / 비용 | B | C | 해석 |
|---|---|---|---|---|
| 세 종목 주 비교 4/9~9/28 | −0.022564% / 2 / $0.032201 | A와 같음 | A와 같음 | 강제 후보가 공통 위험 한도를 통과하지 못해 정책 차이의 수익 효과 없음 |
| KDP/HIVE 보조 최종 구간 3/2~9/28 | −0.105909% / 13 / $0.197949 | −0.439327% / 5 / $0.080380 | B와 같음 | 강제 진입·비용은 줄었으나 순수익은 악화 |
| 사건 기간 4거래일 5분 보조 | −0.670713% / 8 / $0.197058 | A와 같음 | −0.400702% / 2 / $0.040377 | 충돌·반복 청산 감소, 약 0.27%p 덜 손실. 수익 전략의 근거는 아님 |

장기 보조 비교에서 매수 조건 미충족 체결은 8→0건, 다음 일봉 평가 일반매도는 7→0건이다. 다음 일봉을 5분으로 해석하지 않았다. 최대낙폭은 A −1.096930%, B/C −0.955031%, 최악 관측 월은 A −0.707005%, B/C −0.945573%로 지표가 엇갈렸다. 평균 보유시간도 실제 체결 시각이 아닌 일봉 라벨 간격이다.

5분 보조에서는 동시 매도 점수를 가진 진입 6→0건, 다음 평가 일반매도 5→0건, 하드 손절은 2→2건이다. A의 강제 후보는 체결되지 않아 A=B이며 **최소 매수 제거 자체의 효과는 이 표본에서 확인되지 않는다.** C의 최대낙폭은 −0.400702%(A/B −0.746996%). 원화 수익률은 A/B −0.540213%, C −0.269847%로 환율 영향을 별도 반영했다. 평균 모의 보유시간은 A/B 549.375분, C 110분으로, 거래 감소가 무조건 보유시간 연장을 뜻하지 않는다.

주 일봉 비교의 원화 수익률 −8.237002%는 대부분 달러 현금의 환율 변화이며 USD 매매 손실과 구분한다. 완전한 달력월의 월 +10% 관측은 주 비교 **0/4개월**, 보조 최종 구간 **0/5개월**이다. 부분 월을 분모에서 제외했다. 5분 자료는 4거래일뿐이라 월 성과를 계산하지 않았다. 과거 관측 횟수는 미래 달성 확률이 아니다.

CMCSA의 1/5 Versant 분사는 단순 주식 수 분할로 처리할 수 없어 결과 계산 전에 데이터 품질 변경 기록을 남기고 1/6 이후 자료만 주 비교에 사용했다. 64개 준비 봉 뒤 4/9부터 평가하며 원래 학습·검증 날짜를 이동시키지 않아 주 비교의 두 구간은 생략됐다. 따라서 학습 모델의 독립 최종 평가라고 주장하지 않는다. 해당 분사 조정이 없는 KDP/HIVE의 보조 비교는 원래 시간순 세 구간을 유지했고 구간별 우열도 일관되지 않았다. [사전 계획](comparison-frozen-plan.json), [계산 전 변경 기록](comparison-frozen-amendment.json).

비용 스트레스(편도 0.30%, 최소 $0.10, 스프레드·슬리피지 각 30bp)의 최종 구간과 5분 비교는 모두 체결 0건이다. SPY도 8만원·1주·가격 한도로 거래 0건이다. 현금 유지와 FX 변화를 수익 전략의 증거로 삼지 않았다. 확인되지 않은 데이터·서버·AI 운영비는 0으로 넣지 않고 미상으로 남겼다.

지정가 다음 봉 체결, 일봉의 장중 순서 부재, 5분 replay의 다음 관측 봉 미도달 DAY 만료 및 세션 경계 가정, 이전 완성 일봉과 당시 변화하던 일봉의 차이 때문에 정확한 사건 체결 replay는 아니다. 비용·현금·평가액·사유별 계산은 독립 대사했다. 공개 배당 현금은 제외했으며 비교 모의 보유와 배당락일이 겹치지 않았다는 추가 검사도 기록했다.

## 6. 검증과 아직 확인하지 못한 부분

실제 엔진의 최소 매수 예외, B/C의 no_trade·충돌·중복 봉, 새 시세 하드 손절, 미체결 비보유·비손익, 비용·현금·위험·체결 비중, 조회 경로 주문 차단을 회귀와 직접 CLI 사용으로 검증했다. 날짜만 있는 봉이 UTC 자정으로 바뀌는 입력 오류, 기존 결과 파일 덮어쓰기, `.env` 중복 키 우선순위도 실패 재현 후 수정했다.

실행 명령·최종 단일 실행 결과·수정 파일 목록·독립 5개 검토는 [VERIFICATION.md](VERIFICATION.md)에 기록한다. 여러 번 실행한 테스트 수를 합산하지 않는다. 실제 EXE 실행·실주문·실시간 호가 체결·운영 GUI 시각 QA는 수행하지 않았다. LSP 미설치, 기존 타입 경고, 실제 체결 시각·수수료·과거 설정/학습 snapshot·장중 봉 내부 순서 부재는 남아 있다.

## 7. 실거래·배포 보존과 되돌리기

실거래 설정, 보유 종목 정책, EXE, 예약 작업, 승인·계좌 검증·중복 주문 방지는 변경하지 않았다. 일반 최소 매수 기능도 운영 코드에서 삭제하지 않았다. 미커밋 변경을 reset·강제 덮어쓰기·동기화하지 않았고 Git 추가·커밋도 하지 않았다. 기존 배포·설정 파일의 지정 해시를 재검사한다.

실험은 별도 CLI에만 있으므로 **사용을 중단하면 기존 운영 경로가 그대로 남는다.** 실험 JSON을 운영 설정으로 복사하거나 EXE를 교체하면 안 된다. 코드 수준에서 선택적 체결 비중 검사를 사용하지 않으려면 기존 호출처럼 인자를 생략하면 되며 기본값은 None이다. 전체 git reset이나 파일 단위 checkout은 앞선 변경까지 지우므로 복귀 수단으로 쓰지 않는다.

추후 적용 검토에서는 실제 수수료·체결 시각을 별도 확인하고, 더 긴 모의 기간에 강제 진입·충돌·보호 매도·재시작 상태를 관측해야 한다. 운영 적용은 최소 매수 설정 해제와 C의 완성 봉 상태 저장·실시간 보호 분리·진입 점수 진단을 별도 변경으로 검토해야 하며 이번에 연결하지 않았다. 월 +10%나 손절폭 확대의 순수익 개선은 이번 자료로 입증되지 않았다.
