# 자가개선 자동매매 최종 지향점

> 조사 기준일: 2026년 7월 11일
> 대상: `nasdaq-auto-trader`
> 전제: 로컬 실행, 로컬 거대 언어 모델 미사용, 개인용 중앙처리장치·메모리 사용량 제한

> 제품·알고리즘·논문·소스코드의 고유 식별자만 정확한 대조를 위해 원문을 유지하며, 설명은 모두 한글로 적었다.

## 최종 결론

최종 지향점은 **로컬 증거 기반 적응형 퀀트 연구·운영 체계**다.

이 체계는 스스로 코드를 고쳐 실전에 바로 반영하지 않는다. 대신 새 데이터와 체결 결과가 쌓일수록 다음 다섯 가지를 개선한다.

1. 잘못된 전략을 더 일찍 거절한다.
2. 실제 수수료·슬리피지·부분체결을 더 정확히 추정한다.
3. 시장 상태에 맞는 검증된 전략의 비중을 제한적으로 조절한다.
4. 데이터·실험·승격·주문·체결을 완전히 재현한다.
5. 이상 징후가 나타나면 거래를 줄이거나 중단하고 이전 챔피언으로 되돌린다.

**시간이 지날수록 수익이 단조 증가한다는 보장은 불가능하다.** 비정상 시장에서 온라인 학습이 제공하는 보장은 특정 조건에서 비교 대상보다 손실을 얼마나 덜 보는지에 관한 상대적 후회 한계이지 절대 양의 수익이 아니다. 시장 변화량이 시간에 비례해 커지면 장기 평균 최적성도 보장할 수 없다. 따라서 이 프로그램에서 말하는 개선은 **수익 보장**이 아니라 **선택 오류, 비용 추정 오류, 실행 오류, 복구 시간의 감소**다. [비정상 다중 선택 원 논문](https://papers.nips.cc/paper_files/paper/2014/file/91ba7292e5388b90b58d0b839a7f19ec-Paper.pdf), [백테스트 과최적화 확률 원문](https://www.davidhbailey.com/dhbpapers/backtest-prob.pdf)

## 현재 상태 판정

현재 프로그램은 자가개선의 뼈대는 있으나 폐루프는 아니다.

| 영역 | 현재 가능한 것 | 핵심 단절 |
|---|---|---|
| 후보 처리 | 연구 출처와 전략 명세를 검사하고 백테스트한다 | 운영 후보 제공자가 연구 문맥을 버리고 파일만 읽는다 |
| 백테스트 | 알려진 시점까지 계산하고 다음 봉 시가에 체결한다 | 데이터 공급자·수집시각·조정 여부·과거 유니버스 계보가 없다 |
| 검증 | 낙폭·회전율·여러 대리점수를 검사한다 | 실제 정화 교차검증·조합 경로·독립 표본외 검증이 아니다 |
| 승격 | 종이거래 후보 기록과 롤백 뼈대가 있다 | 종이거래→그림자거래→챔피언 운영 상태 전이가 없다 |
| 자동 종목 선택 실행 | 등록된 적격 전략으로 종목을 고르고 제한된 명령줄 경로에서 영속 주문 고유키·중복 거절·재시작 복구를 적용한다 | 이 보호는 별도의 인공지능 퀀트 연구실 실전 주기 전체에 아직 공통 적용되지 않는다 |
| 인공지능 퀀트 연구실 실행 | 별도 보호 조건을 거쳐 한국투자증권 해외주식 주문을 제출할 수 있다 | 이 별도 실전 주기가 자동 종목 선택 경로의 더 강한 영속 주문 허가문을 우회한다 |
| 피드백 | 예상·실제 주문의 슬리피지와 수수료를 계산할 수 있다 | KIS 체결에서 야간 개선 작업으로 이어지는 운영 호출자가 없다 |

따라서 이미 구현된 **과거 데이터 기반 종목 자동 선택**의 주문 안전장치를 폐기하는 것이 아니라, 이를 모든 실전 주문이 통과하는 공통 관문으로 승격해야 한다. 보고서에서 말하는 우회 문제는 `ai-quant live-cycle`이라는 별도 연구실 실전 경로에 한정된다. [자동 선택 안전 동작](../../README.md#자동-종목-선택은-어떻게-작동하나요), [기존 주문 보호 설명](../../README.md#안전-장치와-한계)

직접 실행 검증에서 서로 다른 연구 문맥을 넣어도 파일 후보 제공자의 출력은 같았다. 또한 90개 점이 선형 증가하는 단일 자산곡선만으로 현재 구현의 `purged_cross_validation_score=1.0`, `CPCV=1.0`, `PBO=0.0`, `promotion_eligible=True`가 나왔다. 이 값들은 실제 정화·금지기간·조합 표본외 경로를 수행한 결과가 아니다. [후보 제공자 구현](../../nasdaq_auto_trader/ai_quant_lab/operator_commands.py), [현재 검증 구현](../../nasdaq_auto_trader/ai_quant_lab/validation_engine.py), [실행 검증 기록](../../.omo/ulw-research/20260711-final-target/verify-current-code.md)

## 최종 구조

```text
시장자료·기업행사·유니버스·KIS 체결
                 │
                 ▼
불변 원천 스냅숏 + 시점·품질 검사
                 │
                 ▼
Parquet 사실 저장소 ── DuckDB 분석 ── 특징 버전
                 │
                 ▼
제한된 전략 문법 + 단일 작업 순차 탐색
                 │
                 ▼
실제 순차 표본외 검증 + 정화/금지기간 + CPCV/PBO/DSR/SPA
                 │
                 ▼
SQLite 실험·전략·승격 원장
                 │
                 ▼
종이거래 ── 그림자거래 ── 사람 승인 ── 챔피언
                 │
                 ▼
단일 영속 주문 허가문 + 독립 위험 통제기
                 │
                 ▼
KIS 주문 상태기계 + REST 대사 + 체결 귀속
                 │
                 ▼
비용 모델 보정 + 제한적 전략 가중치 갱신 + 변화 경보
```

핵심 원칙은 **대용량 변경 불가 기록은 파케이(`Parquet`), 운영 상태는 에스큐엘라이트(`SQLite`), 분석은 덕디비(`DuckDB`), 관계의 기준은 관계형 질의(`SQL`) 외래키**다. 덕디비는 파케이의 필요한 열과 행만 읽는 기능을 제공하고 스레드·메모리 상한을 설정할 수 있다. 단, 메모리 상한 밖에서 쓰이는 구조도 있으므로 운영체제 수준 감시가 추가로 필요하다. [덕디비 파케이 문서](https://duckdb.org/docs/stable/data/parquet/overview), [덕디비 자원 설정](https://duckdb.org/docs/stable/configuration/overview), [덕디비 메모리 주의사항](https://duckdb.org/docs/current/guides/performance/oom)

## 반드시 먼저 만드는 단일 원장

모든 결과는 아래 연결을 따라 한 번에 추적되어야 한다.

```text
데이터 스냅숏
  → 전략 버전
  → 제안과 모든 탐색 시도
  → 검증 실행과 각 구간
  → 배포 역할과 위험 정책
  → 신호
  → 주문 의도
  → KIS 주문번호와 정정·취소 계보
  → 부분·완전 체결
  → 비용·손익 귀속
  → 야간 피드백
  → 다음 가중치 또는 재검증 요청
```

### SQLite 제어 원장

| 표 | 저장 내용 |
|---|---|
| `data_snapshot` | 원천 경로, 공급자, 사건시각, 수집시각, 조정 방식, 유니버스, 내용 해시 |
| `strategy_version` | 제한된 전략 문법, 문법 버전, 내용 해시, 부모 전략 |
| `proposal` | 사람·파일·GPT 출처, 입력·출력 해시, 인용 근거 |
| `search_run`, `trial` | 탐색 공간, 난수값, 완료·중단·실패를 포함한 모든 탐색 시도 |
| `validation_run`, `fold` | 학습·검증 구간, 정화·금지기간, 비용 모델, 결과 |
| `deployment` | 후보·종이거래·그림자거래·챔피언·중단 상태 |
| `risk_policy`, `permit` | 위험 한도 버전, 주문 전 허가, 차단 이유 |
| `order`, `fill` | 로컬 의도, KIS 식별자, 상태 변화, 부분체결, 수수료 |
| `feedback_run` | 처리한 체결 범위, 비용 보정, 전략 비중 변화, 재검증 요청 |
| `job_run` | 작업 고유키, 시작·완료 시각, 자원 사용량, 재실행 방지 지점 |

### Parquet 사실 저장소

시장봉, 기업행사, 과거 유니버스, 특징 행렬, 신호, 주문 사건, 체결 사건, 포지션 스냅숏, 수익 귀속, 검증 구간별 수익을 불변 파티션으로 저장한다. 각 파티션은 내용 해시와 명세를 가져야 하며, 같은 입력을 다시 수집했을 때 과거 해시가 바뀌면 승격 작업을 중단한다.

## 전략은 어떻게 발전하는가

### 1. 전략 후보 생성

임의 파이썬 코드를 생성하지 않는다. 이동평균, 상대강도, 변동성, 횡단면 순위, 진입·청산, 보유기간, 포지션 크기처럼 허용된 블록만 조합하는 **형식이 정해진 전략 문법**을 사용한다.

후보 출처는 세 가지다.

- 사람이 작성한 경제 가설
- 기존 챔피언 주변의 제한된 매개변수·구조 변형
- 선택적 GPT 연구 보조가 제안한 전략 문법 초안

모든 후보는 같은 파서, 금지 목록, 복잡도 상한, 미래참조 검사, 내용 해시를 통과한다.

### 2. 제한된 자동 탐색

초기에는 옵튜나(`Optuna`)를 순차 실행해 소수의 매개변수와 문법 선택지만 탐색한다. 빠른 가지치기는 계산량을 줄일 뿐 선택편향을 없애지 않으므로 완료·중단·실패·수동 시도까지 모두 같은 탐색 묶음에 기록한다. 병렬 탐색은 재현성을 떨어뜨리므로 이 컴퓨터에서는 사용하지 않는다. [옵튜나 논문](https://arxiv.org/abs/1907.10902), [옵튜나 공식 표본추출기 문서](https://optuna.readthedocs.io/en/stable/reference/samplers/index.html), [옵튜나 재현성 주의사항](https://optuna.readthedocs.io/en/stable/faq.html)

### 3. 실제 과최적화 검증

현재 대리점수를 다음 순서로 교체한다.

1. 시간 순서를 지킨 순차 표본외 검증
2. 표지 기간이 겹치는 학습 자료 제거와 금지기간
3. 여러 표본외 경로를 만드는 조합 정화 교차검증
4. 탐색된 전략군의 과최적화 확률
5. 비정규성과 다중 시도를 보정한 축소 샤프비율
6. 전략군 전체에 대한 현실성 검사 또는 우월 예측능력 검사
7. 더 높은 비용·슬리피지·지연·결측·기업행사에 대한 스트레스 검사

어떤 하나도 수익을 증명하지 않는다. PBO는 잘못된 백테스트 구현·미래정보·잘못된 거래비용·미래 시장변화를 잡지 못한다. DSR도 누락된 시도를 복구하지 못한다. 따라서 **모든 시도 원장**이 통계식보다 먼저다. [PBO 원문](https://www.davidhbailey.com/dhbpapers/backtest-prob.pdf), [DSR 원문](https://papers.ssrn.com/sol3/papers.cfm?abstract_id=2460551), [White 현실성 검사](https://onlinelibrary.wiley.com/doi/abs/10.1111/1468-0262.00152), [Hansen 우월 예측능력 검사](https://papers.ssrn.com/sol3/papers.cfm?abstract_id=264569)

### 4. 챔피언과 도전자

통과한 전략은 곧바로 실전에 가지 않는다.

```text
연구 후보 → 종이거래 → 그림자거래 → 사람 승인 → 소액 챔피언 → 일반 챔피언
```

도전자와 챔피언은 같은 기간·종목군·비용 모델로 비교한다. 승격 기준은 실험 전에 고정하며 도중에 바꾸지 않는다. 이상 징후가 생기면 새 진입을 막고, 자동 전량 시장가 청산과는 분리해 안전한 취소·대사·청산 절차를 적용한다. 작은 단계 배포와 되돌리기는 결함의 영향을 제한하지만 짧은 표본에서 우월성을 증명하지는 않는다. [Google SRE 단계 배포](https://sre.google/workbook/canarying-releases/), [NIST 인공지능 위험관리 체계](https://www.nist.gov/itl/ai-risk-management-framework)

### 5. 제한적 온라인 적응

충분히 검증된 전략 여러 개의 **비중만** 천천히 갱신한다. 모든 전략의 가상 비용 반영 후 손익을 계산할 수 있으므로 초기에는 결과를 일부만 관측하는 선택 방식보다 전문가 조언 결합이 더 적절하다.

- Hedge: 고정된 최선 전략과의 상대 손실을 줄이는 기준
- Fixed Share: 시장 구간마다 최선 전략이 바뀌는 상황을 제한적으로 추적
- ADWIN: 손익·특징·자료 품질 변화 경보

이 기능은 비용 포함 동일비중 기준선을 그림자거래에서 이긴 뒤에만 켠다. ADWIN은 자동 승격이나 전액 교체를 하지 않고 **경보 → 도전자 동결 → 재검증**만 수행한다. [Hedge 원문](https://www.eecs.harvard.edu/cs286r/courses/fall10/papers/hedge.pdf), [ADWIN 원문](https://epubs.siam.org/doi/abs/10.1137/1.9781611972771.42), [River 논문](https://www.jmlr.org/papers/v22/20-1380.html)

## KIS 주문과 체결 폐루프

모든 실전 주문은 하나의 영속 주문 게이트를 거친다. 같은 신호를 다시 실행해도 한 번만 주문되며, 시간은 UTC 정규형으로 바꾼 뒤 고유키를 계산한다.

한국투자증권 주문 응답의 지점번호·주문번호·주문시간을 즉시 저장한다. 정정·취소는 원주문번호를 입력받고 새 주문번호를 반환하므로 부모-자식 계보를 보존한다. 주문 응답이 시간초과되거나 식별자가 빠지면 같은 주문을 다시 보내지 않고 `응답 불명`으로 둔 뒤 미체결·주문체결내역의 모든 페이지를 조회해 대사한다. 실시간 통보(`WebSocket`)는 빠른 실시간 알림 사건으로 보존하되 종결 상태는 웹 조회(`REST`) 대사로 확정한다. [한국투자증권 공식 저장소](https://github.com/koreainvestment/open-trading-api), [해외주식 정정취소 예제](https://github.com/koreainvestment/open-trading-api/blob/main/examples_llm/overseas_stock/order_rvsecncl/order_rvsecncl.py), [해외주식 미체결 예제](https://github.com/koreainvestment/open-trading-api/blob/main/examples_llm/overseas_stock/inquire_nccs/inquire_nccs.py), [해외주식 체결내역 예제](https://github.com/koreainvestment/open-trading-api/blob/main/examples_llm/overseas_stock/inquire_ccnl/inquire_ccnl.py), [한국투자증권 오류 코드](https://apiportal.koreainvestment.com/faq-error-code)

## 온톨로지·SQL·벡터·그래프의 역할

| 기술 | 최종 판정 | 정확한 역할 | 도입 조건 |
|---|---|---|---|
| 관계형 질의(`SQL`) | 즉시 채택 | 하나의 기준 원장, 외래키, 상태 전이, 감사 질의 | 처음부터 사용 |
| 경량 온톨로지 | 제한 채택 | 종목·전략·지표·사건·차단 이유의 버전 어휘 | SQL 열거형과 명세부터 시작 |
| PROV-O 개념 | 채택 | 개체·활동·책임 주체로 계보를 일관되게 설계 | 별도 RDF 저장소 없이 SQL에 반영 |
| RDF·OWL·SHACL | 보류 | 여러 기관의 의미 충돌과 그래프 제약 검사 | SQL 제약으로 표현하기 어려운 실제 사례가 생길 때 |
| 속성 그래프 | 보류 | 복잡한 다단계 계보 탐색 | 반복 질의가 SQL의 측정된 병목일 때 |
| 전문 벡터 저장소 | 기본 불채택 | 논문·사후분석의 의미 검색 | 대표 질의 평가에서 SQLite 전문검색을 유의하게 이길 때 |
| SQLite 전문검색 | 조건부 채택 | 한글 연구 메모·인용·사고 기록의 키워드 검색 | 문서가 쌓여 검색 필요가 생길 때 |

온톨로지는 유용한 **공통 언어**지만 알파를 만들지 않는다. W3C PROV-O의 개체·활동·책임 주체는 데이터 스냅숏, 검증 실행, 전략 제안자의 계보에 잘 맞는다. SHACL은 RDF 자료를 모양 제약으로 검사할 수 있지만 현재 규모에서는 SQL 외래키·검사 제약·JSON 명세가 더 단순하다. [W3C PROV-O](https://www.w3.org/TR/prov-o/), [W3C OWL 2](https://www.w3.org/TR/owl-primer/), [W3C SHACL](https://www.w3.org/TR/shacl/), [SQLite FTS5](https://www.sqlite.org/fts5.html)

## 외부 언어 모델과 사용자 위임 인증 판정

**OAuth로 OpenAI REST API를 추가 과금 없이 쓰는 공식 방법은 확인되지 않았다.** OpenAI API는 API 키를 사용하는 별도 과금 제품이며 ChatGPT 구독과 청구 체계가 분리되어 있다. OAuth는 외부 서비스 인증이나 ChatGPT 앱 연결에서 쓰일 수 있지만 API 비용 면제를 뜻하지 않는다. [OpenAI API 빠른 시작](https://platform.openai.com/docs/quickstart/make-your-first-api-request), [ChatGPT와 API 별도 과금](https://help.openai.com/en/articles/8156019-is-api-usage-included-in-chatgpt-subscriptions-even-if-i-have-a-paid-chatgpt-account), [청구 체계 안내](https://help.openai.com/en/articles/9039756)

코덱스(`Codex`)는 챗지피티(`ChatGPT`) 로그인으로 요금제에 포함된 사용량을 쓸 수 있지만 사용량 제한과 추가 크레딧 체계가 있는 **개발용 작업 도구**다. 프로그램의 외부 언어 모델 접속 인증이나 거래 실행 환경으로 간주하지 않는다. 개발·검토·수동 연구에만 사용한다. 자동 충전을 끄면 포함량 초과 시 기다리거나 명시적으로 크레딧을 구매하는 방식으로 추가 지출을 통제할 수 있다. [챗지피티 요금제로 코덱스 사용](https://help.openai.com/en/articles/11369540-using-codex-with-your-chatgpt-plan), [코덱스 크레딧 안내](https://help.openai.com/en/articles/12642688-using-credits-for-flexible-usage-in-chatgpt-plus-pro)

오픈에이아이 응용프로그램 인터페이스(`OpenAI API`)를 선택적으로 붙인다면 허용 범위는 전략 문법 초안, 실패 실험 요약, 논문 분류다. 출력은 검증되지 않은 입력으로 취급해 파서·허용목록·자원 상한·별도 검증을 통과해야 한다. 실시간 시세, 직접 주문, 위험 우회, 챔피언 승격, 비밀키와 원시 계좌자료 전송에는 사용하지 않는다.

## 현재 PC 자원 정책

현재 PC는 논리 프로세서 4개, 메모리 약 15.9GB다. 기본 연구 정책은 다음과 같이 고정한다.

| 항목 | 기본값 |
|---|---:|
| 동시에 실행하는 연구 작업 | 1개 |
| DuckDB 스레드 | 1개 |
| DuckDB 메모리 상한 | 3GB |
| 작업 감시 종료 상한 | 실제 사용 메모리 4GB |
| Optuna 병렬 수 | 1 |
| 1회 탐색 | 최대 25회 또는 30분 |
| 동시 도전자 | 1개 |
| 임시 저장 한도 | 5GB |
| 실행 우선순위 | 낮음 또는 보통 이하 |

연구 작업은 거래 프로그램이 정지되어 있고, 장 마감 후 한국투자증권 대사와 감사 기록이 완료됐으며 미확정 주문이 없을 때만 시작한다. 가용 메모리가 부족해도 시작하지 않는다. 작업이 시간·메모리·디스크 상한을 넘으면 해당 탐색만 실패 처리하며 챔피언과 거래 실행 환경은 그대로 유지한다.

## 구현 순서

### 1단계: 주문과 상태 무결성

- AI 실전 경로를 기존 영속 주문 허가문·중복방지·재시작 불명 상태 처리에 통합
- KIS 주문·정정취소·미체결·체결내역·실시간 통보 어댑터와 대사 상태기계 구축
- 실전 자료에 백테스트와 같은 시각·정렬·유한값 검사 적용
- 레지스트리 쓰기를 트랜잭션 또는 원자 교체로 변경

완료 기준: 같은 신호를 여러 번 재실행해도 주문이 한 번만 발생하고, 임의 주문 하나를 신호부터 체결·손익까지 재현한다.

### 2단계: 자료와 실험 계보

- 불변 Parquet 스냅숏과 SQLite 제어 원장 도입
- 사건시각과 수집시각 분리, 과거 유니버스·기업행사·조정 방식 저장
- 모든 수동·자동·중단·실패 탐색 시도와 비용 모델 버전 저장
- 야간 작업 고유키와 체결 처리 지점 도입

완료 기준: 같은 스냅숏·전략·비용 모델·난수값으로 같은 결과가 나오며 야간 작업 재실행이 중복 피드백을 만들지 않는다.

### 3단계: 검증 엔진 교체

- 현재 대리점수를 실제 순차 표본외·정화·금지기간·CPCV/PBO·DSR·SPA로 교체
- 미래정보가 섞인 합성 자료가 반드시 탈락하는 회귀 검증 추가
- 비용·슬리피지·자료 결측·시장 구간 스트레스 검사 추가

완료 기준: 검증 구간과 제거된 표본을 모두 출력하고, 현재 대리점수는 승격 근거로 사용할 수 없다.

### 4단계: 제한된 후보 탐색과 단계 승격

- 형식이 정해진 전략 문법과 순차 Optuna 탐색 도입
- 종이거래·그림자거래·사람 승인·소액 챔피언 상태 전이 구현
- 챔피언과 동일 기간·종목군·비용 모델 비교

완료 기준: 최소 30 거래 세션과 100개 실행 가능 판단에서 오래된 자료 주문, 위험 한도 위반, 미대사 포지션이 0건이다.

### 5단계: 제한적 온라인 적응

- 체결 귀속으로 비용 모델 보정
- 비용 포함 동일비중 기준선과 비교한 Hedge 또는 Fixed Share 그림자 평가
- ADWIN을 경보·동결·재검증에만 연결

완료 기준: 정적 기준선보다 비용 반영 후 결과가 좋아지고 회전율·집중도·낙폭 상한을 지키는 경우에만 비중 갱신을 활성화한다.

### 6단계: 선택적 의미 검색과 GPT

- 연구 메모는 SQLite 전문검색부터 시작
- 측정된 필요가 있을 때만 벡터 또는 그래프 투영 도입
- OpenAI API는 별도 예산을 명시한 오프라인 연구 보조로만 도입

완료 기준: 벡터·그래프·GPT가 꺼져도 검증·승격·거래·복구가 완전히 동작한다.

## 즉시 거래 중단 조건

다음 조건에서는 **새 주문을 즉시 차단**하고 포지션 청산은 별도 정책으로 판단한다.

- KIS와 로컬 현금·포지션이 대사 시간 안에 일치하지 않음
- 미귀속 체결, 중복 주문 고유키, 단계 역행
- 원천 자료 해시·명세·시계·시장시간 이상
- 위험 통제 상태 불명, 심박 상실, 감사 로그 쓰기 실패
- 같은 사건 재생에서 백테스트와 실전 신호가 다름
- 비용·슬리피지·거부율·회전율이 승인 범위를 넘음
- 일손실·낙폭·노출·주문률 상한 도달
- KIS 주문 응답 불명, 페이지 대사 미완료, 인증 이상
- 전략·자료·비용 모델·위험 정책 버전을 재현할 수 없음

## 성공을 측정하는 지표

| 목적 | 측정값 |
|---|---|
| 선택 품질 | 미접촉 표본외 성능, DSR, PBO, SPA, 승격 후 성능 열화 |
| 실행 품질 | 예상 대비 실제 슬리피지, 부분체결률, 거부율, 미대사 주문 수 |
| 안전 | 위험 위반, 오래된 자료 주문, 중복 주문, 감사 실패 수 |
| 적응 | 비용 반영 후 정적 기준선 대비 상대 손실, 비중 회전율, 유효 전략 수 |
| 재현성 | 동일 입력 재실행 일치율, 완전 계보율, 중복 피드백 수 |
| 자원 | 후보당 중앙처리장치 시간, 최고 메모리, 임시 디스크, 중단된 탐색 수 |

가장 중요한 지표는 누적 수익 하나가 아니다. **나쁜 후보를 더 잘 거절하고, 실전과 연구의 차이를 줄이고, 이상 시 더 빨리 안전하게 멈추는가**가 이 시스템의 진짜 자가개선이다.
