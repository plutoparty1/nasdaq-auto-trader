# 로컬 체결 증거 및 조기 매도 로그 감사

조사일: 2026-09-29. 로컬 파일만 읽었으며 브로커 조회, 주문, 취소, 예약 작업, 실행 프로그램 시작은 하지 않았다. 이 문서의 주문 관측은 실제 체결이나 실현손익으로 집계하지 않았다.

## 결론

요구한 최근 **실제 체결 기준 청산 20~30건은 현재 저장 자료로 복원할 수 없다.** 원장 요건을 충족한 완결 거래는 0건이다. 이는 실제 거래가 없었다는 뜻이 아니라, 평균 체결가·체결 시각·체결 수량·수수료가 함께 보존되지 않았다는 뜻이다. `fills.csv`는 이 이유로 헤더만 있다. 손익을 0으로 채우지 않았다.

그럼에도 최근 조기 매도 **주문 판단 원인**은 일부 확인된다. 9월 23~25일 세 사례 모두 `below_long_regime` 상태에서 `daily_minimum_best_affordable`로 1주 매수를 제출한 뒤 다음 약 5분 평가에서 일반 기술적 매도를 제출했다. 해당 매도 기록에는 고정 손절·ATR 손절·트레일링 이유가 없다. 매수와 매도 때 판단 가격의 변화는 각각 -0.3812%, -0.6855%, +0.3841%다. 따라서 이 세 주문 판단을 “매수가 대비 -5% 하락에 따른 매도”로 설명하는 것은 로그와 맞지 않는다. 실제 체결가 기준 가격 변화와 순손익은 별도로 미확인이다.

## 데이터 품질과 미확인 항목

- **평균가 반영 지연/부분 체결:** 최근 3개 매도는 일반 보유 상태를 전제로 한 판단으로 보이나, 잔고 변화와 체결원장이 보존되지 않아 평균가 반영 지연이나 부분 체결의 영향을 사후 확인할 수 없다. 현재 `automatic_buy_receipts.py:127`은 미확인 매수 receipt를 대사하지만 `trading_session_store.py:159`의 `resolve_buy_receipt()`는 완료 후 receipt를 null로 지운다. 해소된 상태와 영구 체결 증거는 다르다.
- **시세 신선도:** 감사 이벤트 시각, 신호 시각, 판단 가격은 일부 있지만 해당 가격의 거래소 timestamp/bid/ask/provider 및 봉 완성 상태는 최근 일반 매도 기록에 없다. 오래된 시세였는지 단정하지 않는다. 신호의 `@...13:40...` 접미사는 실행 슬롯 식별일 수 있어 “실제 5분봉 지표”의 증거가 아니다.
- **통화/수량:** 최근 요청은 미국주식 1주로 보인다. 판단가 USD의 통화 근거는 KIS 해외주식 실행 경로다. 로컬 원장에 실제 환전/결제환율·원화 기준 평가액·외부 입출금 내역은 없다. 가격 변화율을 원화 계좌 수익률로 변환하지 않았다.
- **비용:** 실제 약정 수수료, 최소 수수료, 세금, 환전 비용 없음. 계획의 `fee_buffer_usd`/`fee_buffer_pct`와 학습의 `commission_bps`는 실청구 수수료가 아니다.
- **중복 주문:** 원 감사 로그 18건에 동일 종목·방향·신호시각 조합의 중복 제출은 없었다. 이는 거래소 전체 주문에 중복이 없었다는 증명은 아니다. 모니터의 repeated already_sold를 거래로 중복 집계하는 오류는 배제했다.
- **계좌 성과:** 마지막 계좌 스냅샷 2026-09-25 23:44:07 UTC는 cash/equity/buying_power 모두 63.09다. 입출금·FX 시계열이 없으므로 초기 80,000원 대비 수익으로 계산하지 않았다. 6,504개의 스냅샷이 있어도 외부 현금흐름을 제거한 월 수익률을 정확히 복원할 수 없다.

## 백테스트 가능한 원자료

APP 하위와 REPO의 거래 관련 경로에서 CSV/parquet/feather/sqlite/db 파일을 열거했다. `.git`, `node_modules`, `_internal`, 관련 없는 gp5 프로젝트, 외부 gs-quant 연구 샘플은 가격 자료로 사용하지 않았다. APP에는 해당 형식의 가격 파일이 없었다. REPO의 `.omo/evidence/live-runtime-20260908/inputs/bars.csv`는 QQQ 10행(2026-01-01~01-10), 가격 100→110, 주말 포함의 QA fixture다. 실제 역사 데이터로 사용하면 안 된다. 다른 CSV는 GUI 프로세스 관측 및 QA 목록이고 DB는 codegraph다.

최근 학습 보고서 `APP/ai_quant_lab/strategy_specs/reports/builtin_trend_following-data-84f6b08a211c48fe.json`은 2026-09-25 20:05:39 UTC 작성, 데이터 기간 2026-06-29~09-25를 기록한다. 내용은 `single_backtest_in_sample`; 홀드아웃은 `holdout_history_insufficient`, available 63봉/required 306봉으로 실패했다. commission 1bp/slippage 5bp는 설정 가정이다. `learning_report.py:34`는 기간만 추출하며 `:35` 이후에 원 OHLC를 저장하지 않는다. 최근 기록된 총수익률이나 trade_count를 새 실험 후보의 성과 증거로 재활용할 수 없다.

아직 읽지 않은 모든 JSON/QA 증거에 유효한 가격 데이터가 전혀 없다는 전면적 주장까지 하지는 않는다. 현재 확인된 운영 저장 구조에는 비교 실험에 필요한 재현 가능한 raw OHLC, 시점별 편입 종목 정보, 환율·비용 시계열이 없다. 합성 데이터 기능 시험과 실제 성과 백테스트를 구분해야 한다.

## 추가로 필요한 저장과 검증 절차
