# 조기 매도 분석과 오프라인 개선 결과

기준: 2026-09-29, `C:/Users/u/nasdaq-auto-trader`의 현재 로컬 소스·배포 설정·저장 로그. 이 문서는 실제 체결 성과와 주문 판단 증거를 구분한다. 실주문, 취소, 예약 실행, 승인 갱신, 실거래 전환, EXE 재배포를 하지 않았다. 기존 미커밋 변경 및 실거래 설정을 보존했다.

## 다섯 질문에 대한 답

1. **왜 짧은 시간 안에 매도됐는가?** 최근 9/23~25 주문 판단 세 쌍은 매수 점수0·`below_long_regime`인데도 `daily_minimum_best_affordable` 정책으로 1주 매수 제출 후, 약5분 뒤 매도 점수6~7의 일반 기술적 신호로 매도 제출했다. 최소 일일 매수 정책과 청산 조건의 충돌이 관측된다. 실제 체결 시각/단가 원장이 없으므로 이를 확정 체결 보유시간이나 실현손익으로 바꾸어 말할 수는 없다.
2. **고정5% 손절이 원인인가?** 실제 저장된 배포 GUI 설정의 개별 고정 손절은 **3%**다. GUI 계좌 일일손실 제한5%, 고정 익절5%, 일일 최소 매수 거래당 위험5%는 서로 다른 값이다. 자동선정에는 추가 계좌 일일손실2% 제한도 있다. 최근 세 매도 판단 이유는 고정 손절이 아니다. 과거 여섯 매도 제출은 이유 미기록으로 미확정이다. ATR/트레일링이 작동할 수 있음은 별도 재현으로 확인했다.
3. **오류 수정만으로 바뀐 것은?** 실제 일반 엔진에서 매도까지 매수 가능금액 API 장애로 막히던 의존성을 제거하고 판단 근거 로그를 추가했다. 공통 CSV 백테스터의 수량 주문·비용·잔고/부분매도·고점/예약 처리를 고쳤다. ATR0/비정상 값과 급락 시 트레일링 공백의 교정은 `corrected_exits`를 명시한 오프라인 기준선에 적용한다. 기존 실거래 정책 기본값은 바꾸지 않았다. 손절8%/10%, 진입 ATR 고정, 진입 충돌 거부는 별도 전략 실험이다.
4. **손절폭 확대가 순수익 개선인가, 손실 확정을 미룬 것인가?** 현재 자료로는 판정 불가다. 넓은 손절은 기술적 매도와 일일 강제 진입의 충돌을 해결하지 않는다. 손절 폭만 늘려 동일 수량을 유지하면 계획 손실이 늘어난다. 같은 계좌 위험예산으로 수량을 줄이거나 1주도 초과하면 건너뛰어야 한다. 평가에서 미실현손실을 포함하고 장기 미청산·거래0건을 성과로 인정하지 않는다.
5. **월+10% 근거와 손실 위험은?** 8만원의 목표금액8천원은 산술 목표다. 신뢰할 만한 과거 전략 비교·최종 평가 결과가 없어 달성 빈도나 미래 확률을 제시할 근거가 없다. 2%/4% 거래 위험은 1,600/3,200원이며, 갭·미체결·비용·환율 때문에 실제 손실은 이를 넘을 수 있다. 과거 월+10% 달성 비율을 나중에 계산해도 미래 확률이나 보장수익률은 아니다.

1주 가격이 그 금액을 초과하면 매수하지 않는다. 손절폭이 넓다고 1주를 강제로 사거나 위험예산을 올리지 않는다. 계좌 평가액 기준2% 손실을 연속5회 겪으면 비용 전 약−9.61%, 4%면 약−18.46%다. 실제 갭/체결 비용을 고려하면 더 나빠질 수 있다. 이는 발생 확률이나 미래 손실 예측이 아닌 복리 산술이다.

현재 기본 거래당1%와 일일 최소매수5%를 새 실험2%/4%와 구분해야 한다. 종목당50%, 총노출50%, 현금여유5%가 현재 로컬 제한이다. 실험 프로필의 추가 현금여유·동시 초기위험·월 손실 신규매수 중단은 선택 가능한 제안이며 실전 한도 확정이 아니다.

한국투자증권 공개표에는 미국 온라인0.25% 및 매도 SEC fee가 안내되어 있지만, 실제 계좌의 협의/이벤트 수수료·최소수수료·반올림은 로컬 자료로 확인되지 않았다. 공개표와 학습 설정의 1bp 가정을 실제 청구값으로 사용하지 않는다. 실험 입력에 사용한 수수료·최소수수료·스프레드·슬리피지를 별도 기록한다. [공식 수수료·시세 안내](https://securities.koreainvestment.com/main/bond/research/_static/TF03ca050000.jsp) (2026-09-29 조회).

운영비 역시 실제 결제자료가 없어 0원이라고 확정하지 않는다. 무료 시세와 유료 시세가 모두 가능한 공식 안내만으로 이 계좌의 구독 여부를 알 수 없다. 서버/AI/데이터 비용을 입력하면 거래손익과 따로 차감해야 하며 새 유료 서비스는 추가하지 않았다. 환율 기준과 출처는 CLI에서 명시하고, 실제 환율 이력이 없으면 원화 수익은 고정환율 환산 시나리오로만 표시한다.

## 실험과 복귀

새 프로필은 `experiments/early_exit/`에만 두며 `dry_run=true`를 강제하는 오프라인 CLI에서 사용한다. 기존 GUI 설정, LocalAppData, 승격 전략, 승인 파일 및 배포 EXE에는 연결하지 않았다. 실험 종료 후 기존 실행 경로를 그대로 쓰면 기존 전략이다. 기존 파일 전체를 git reset/checkout으로 되돌리면 사용자의 미커밋 작업을 잃으므로 그런 복구를 하지 않는다.

보유 중인 실제 종목에 진입 ATR을 사후 추정하여 소급 적용하지 않는다. 저장 상태의 프로필 해시가 다르면 새 실험 상태로 임의 재사용하지 않는다. 실험 초기 손절과 추적 최고가 갱신은 별도 상태이며 부분매도는 잔여 상태를 유지한다.

최종 검토에서 추가 매수의 위험 사전 검사도 유지되는 실제 손절선을 쓰도록 고쳤다. 비상 손절 가격은 첫 체결에 별도 고정하며 평균단가가 바뀌어도 낮아지지 않는다. 상태 형식 v2는 이전 형식을 추정 변환하지 않고 거부한다. 기준선 의미를 혼동시키는 `legacy + emergency_stop` 조합도 거부한다.

## 추가 데이터와 모의 운용 확인

필요 자료는 주문/체결 연결 키, 매수·매도 실제 체결시각과 누적/개별 수량, 평균 체결가, 수수료/제비용, 환율/환전비용, 입출금, 당시 유효 설정/버전, 시세 원천 시각, 보유·초기 ATR 상태, 당시 선정 가능한 종목과 point-in-time OHLC다. 계좌번호·자격증명은 필요 없다.

신규 진단 로그는 두 점수·고정/ATR 손절/익절·실효 손절·고점·트레일링·설정 해시·봉 시각/주기·평가 시각을 남긴다. 잔고 평가액에서 얻은 가격은 timestamp가 없으므로 `null`로 기록한다. 관측시각을 시세 생성시각으로 꾸미지 않는다. 실제 체결 영수증은 별도 대사해야 한다.

진단용 지표 계산이 실패해도 유효한 보호 주문 결과를 예외로 덮지 않는다. 잘못된 과거 가격은 점수를 미확인으로 표시한다. 보존한 legacy 모드에서 ATR0이 실제 임계값으로 사용되는 경우에는 `raw_atr_value=0`, `invalid_nonpositive_legacy_active`와 해당 임계값을 표시하여 교정 모드의 정상 보호로 오인하지 않게 했다.

모의 운용에서 확인할 것은 최소매수 진입 veto가 일일 정책에 의해 다시 BUY로 바뀌지 않는지, 완성봉 중복평가와 하드 보호의 독립성, 재시작/부분체결 상태, 지정가 미체결과 gap 손실, 보유분 관리와 신규 매수 중단의 분리, 승인/계좌/pending/dedup 차단 이유다. 실전 적용 전에는 실제 수수료와 환율, 배포 EXE와 소스 동일성, 현재 보유분의 별도 정책, 계좌 전체 위험 한도를 검토해야 한다.

**현재 결론: 원인을 설명하는 주문 판단 근거와 코드 재현은 확보했지만, 수익 개선 및 월+10% 달성 근거는 없다.**
