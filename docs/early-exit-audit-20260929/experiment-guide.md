# 조기 매도 실험 실행 안내 (2026-09-29)

현재 로컬에 실제 과거 성과 비교에 필요한 원시 OHLCV 이력이 확인되지 않았다. 이 문서와 합성 실행 결과는 재현 가능한 검증 도구의 동작 증거이며, 손절 확대의 수익 개선이나 월 +10% 달성 근거가 아니다. 이전 학습 결과의 요약 숫자로 원시 가격·체결 순서를 복원하지 않았다.

## 실행 범위와 안전 경계

`scripts/run_exit_experiments.py`는 오프라인 CSV 전용 진입점이다. 설정은 명시된 `experiments/early_exit/settings.json`, 후보는 `experiments/early_exit/profiles.json`에서 읽는다. 두 파일 모두 `dry_run: true`, `broker: offline_csv`가 필수다. 실제 `.env`, 계좌 설정, GUI 설정, 자동매매 엔진 및 브로커 팩토리를 로드하지 않는다. 애플리케이션의 `__init__`가 실거래 엔진을 import하므로 전용 스크립트는 그 초기화를 우회해 순수 계산 모듈만 로드한다. Python audit hook은 소켓 및 자식 프로세스 생성을 거부한다. 별도 프로세스 회귀 테스트에서 엔진/설정 모듈 미로드와 실제 소켓 생성 차단을 확인한다.

이 경로는 실거래 승인·보유 정책·주문 제한을 변경하지 않으며 GUI/EXE/예약 작업에 연결하지 않았다. 기존 운용으로 복귀하는 조작은 필요 없다. 새 프로필을 기존 실거래 설정 파일에 복사하거나 실행 파일에 자동 반영하지 않는다. 일반 전략의 `corrected_exits=False`가 기존 동작을 보존하고, 수정 기준선은 별도 실험에서만 True로 지정한다.

## 비교의 의미와 한계

모든 후보는 같은 OHLCV, 기술적 진입 점수/지표, 종목 집합, 정수 주문 단위, 동일한 수정 체결·비용 엔진을 쓴다. 첫 비교는 같은 1주 수량이다. 이후 별도로 2%/4% 계획 위험에 따라 정수 수량을 줄인다. 1주라도 예산을 초과하면 건너뛴다. 청산 차이로 현금과 재진입 가능 시점은 달라질 수 있으므로 모든 후보의 실제 체결 날짜가 같다는 뜻은 아니다.

`technical_intended_exits`는 일반 TechnicalStrategy의 의도된 청산 규칙 기준선이다. 실제 현재 운용 전체를 재생했다는 의미가 아니다. 실운용의 매일 최소 1주 매수, 학습 기반 후보 선정, 현재 보유 종목 특별 정책, 체결 대사, 실시간 매도 모니터는 이 일봉 실험에 포함되지 않는다. 현재 종목을 과거에 소급 선정하지 않는다. 실제 전체 경로 비교에는 시점별 선정/매수 의사결정 기록과 당시 이용 가능했던 종목 집합이 추가로 필요하다. 최소 2종목 강제 보유나 현금 부족 교체매매가 현재 구현되어 있다고 가정하지 않는다.

| 후보 | 초기 손절 | 고정 익절 | 트레일링 활성화 / 최고가 하락 | 기타 |
|---|---:|---:|---:|---|
| technical_intended_exits | 고정 3% + 현재 ATR 독립 검사 | 5% + 현재 ATR 검사 | 2% / 1% | 로컬 적용 기술적 수치, 기존 의도 동작 |
| technical_corrected_exits | 동일 | 동일 | 동일 | 오류 수정만 적용, 기준선 위험수량 max 계산은 보수적으로 보존 |
| fixed_8 | 고정 8% | 16% | 8% / 4% | ATR 중복 손절 없음 |
| fixed_10 | 고정 10% | 20% | 10% / 5% | ATR 중복 손절 없음 |
| entry_atr14x3_1day | 진입 신호까지 완성된 1일봉 ATR(14) × 3 | 16% | 8% / 4% | 진입 체결가 기준 폭 0.5%~10% 밖이면 진입 거부 |

ATR 후보의 ATR 값은 진입 신호에서 동결하고 실제 체결가에 초기 손절을 고정한다. ATR 값이 무효이거나 실제 체결가 기준 허용 폭을 벗어나면 주문을 거부한다. 이후 변동성 변화로 초기 손절을 재계산하지 않는다. 추적 보호의 최고가는 별도로 관리한다. ATR 후보의 익절/트레일링은 fixed_8과 같아 초기 손절 방식 차이를 해석할 수 있다. 이 숫자는 사전 정의 후보이며 최적화 결과가 아니다.

기준 전략은 SMA 5/20, EMA 5/20, 장기 SMA 20, 매수 점수 5, 매도 점수 4다. 기타 지표 기간은 StrategyConfig 기본값을 보존한다. 런마다 펼쳐진 최종 설정을 `protocol.json`에 저장한다. 가격 비율은 8% = `0.08`처럼 양의 소수 비율이며 손절 가격은 `매수가 × (1 - 0.08)`다.

`--compare-entry-gate`는 본 5개 청산 비교와 구별된 후보 2개를 추가한다. 하나는 fixed_8에 이미 강한 매도 신호의 진입 차단만 추가하고, 다른 하나는 fixed_8에 완성된 새 봉에서만 일반 매도 재판단을 추가한다. 두 변경을 동시에 묶지 않는다. 일봉 이벤트는 이미 봉당 1회 평가하므로 두 번째 후보는 이 러너에서 차이가 없을 수 있다. 같은 봉 반복 평가는 별도 전략 회귀 테스트로 확인해야 한다.

## 8만 원 위험예산과 제안 한도

실거래 한도 변경 승인이 아니다. 비교 대상 모두 동일한 실험 한도를 사용한다. 로컬 현재 총 투자 상한 50%는 유지했다. 실험 종목당 50%는 한 종목이 그 총 상한까지 점유할 수 있도록 한 제안값이며, 현재 모든 종목/보호 정책과 동등하다고 가정하지 않는다.

| 항목 | 실험 설정 | 의미 |
|---|---:|---|
| 시작 평가액 | 80,000 KRW 상당 | 각 train/validation/final 구간은 독립적으로 같은 금액으로 시작 |
| 거래당 계획 손실 | 평가액 2% 또는 4% | 최초 각각 1,600원 / 3,200원 |
| 종목당 최대 비중 | 50% | 주문 수수료까지 여유를 두어 제한 |
| 계좌 총 투자 비중 | 50% | 기존 보유와 같은 시점 예약 주문 포함 |
| 최소 현금 여유 | 10% | 총 투자 50% 상한이 더 강하게 작동할 수 있음 |
| 동시 보유·예약 계획 위험 | 평가액 6% | 첫 평가액 기준 4,800원, 갭 손실의 절대 상한은 아님 |
| 월 손실 신규 매수 중단 | 월초 기준 평가액 대비 -10% | 이전 월 마지막 평가액을 기준으로 첫날 갭 손실도 포함; 해당 월 재매수 중단 |
| 추가 매수/레버리지 | 사용 안 함 | 현금 계좌 정수 주식만 비교, 손실 후 배증 없음 |

계획 손실은 `수량 × (매수가 - 초기 손절가) + 예상 왕복 비용`이다. 수량 계산은 각 1주의 왕복 수수료 최소액까지 포함하는 보수적 상계를 사용하므로 여러 주 주문에서는 실제 한 주문 최소 수수료보다 과대 추정할 수 있다. 체결 비용은 실제 모의 주문별 최소 수수료로 계산하며 중복 차감하지 않는다. 기준선은 기존 max 위험거리를 보존해 max→min만 바꾸어 주문량을 늘리지 않는다. 새 fixed/entry ATR 후보의 거리와 초기 손절은 같은 정책을 사용한다. 신호 시점과 체결 시점의 거래별·총 위험을 모두 검사한다.

예를 들어 환율을 시장 사실이 아닌 1 USD = 1,400 KRW라는 계산 가정으로 두고 기본 비용을 적용하면, $10 주식 1주의 보수적 계획 손실은 8% 손절 약 1,228원, 10% 손절 약 1,506원이다. $20 주식은 약 2,455원 / 3,013원으로 2% 예산을 초과해 건너뛰지만 4% 예산 안에는 들어온다. 최종 수량은 비중과 현금 조건도 동시에 만족해야 한다.

월간 매수 중단은 현재 봉 종가 평가에서 적용한다. 이전 봉에서 제출한 DAY 주문은 당일 체결 가능 이벤트 후 종가 평가를 받으므로, 월초 장중 갭이나 손실 한도 도달 전에 신규 체결되는 경로를 완전히 차단한다고 주장하지 않는다. 보호 매도는 이 매수 중단으로 막지 않는다.

## 데이터·비용·환율 준비

OHLCV CSV 필수 열은 `symbol,timestamp,open,high,low,close,volume`이며 ISO 8601 시각을 권장한다. 중복 종목/시각, 잘못된 OHLC, NaN/음수 가격은 기존 CSV 로더가 거부한다. 모든 후보는 같은 파일을 사용한다. 일봉 실험은 동일 종목·UTC 날짜에 여러 봉이 있으면 거부하므로 5분봉을 일봉으로 잘못 라벨한 입력을 그대로 평가하지 않는다. 다만 날짜별 1개만 있는 주봉·월봉·누락된 일봉을 자동 구분하지는 않으므로 공급자의 실제 1Day 주기와 거래일 누락을 별도로 검증해야 한다. 상승·하락·횡보 구간과 충분한 초기 지표 계산 이력이 필요하다. 생존 편향을 피하려면 상장폐지 종목과 당시 이용 가능 종목 집합, 배당/분할 조정 기준을 함께 기록해야 한다.

`provenance.example.json`을 별도 복사해 공급자/수집일, 시점별 종목 선정 근거, 조정 정책을 작성한다. REPLACE 문구를 남기면 실행을 거부한다. 단순히 survivorship_corrected를 True로 적었다고 검증된 것은 아니며 manifest는 여전히 검토가 필요한 탐색 결과로 표시한다. 현재 종목 목록을 과거 전체에 적용한 결과를 실운용 증거로 인정하지 않는다.

기본 비용은 온라인 수수료 편도 0.25%, 최소 수수료 $0, 전체 호가 스프레드 10 bps, 편도 추가 슬리피지 10 bps의 **시나리오**다. 0.25%는 공개 요율을 참고한 가정이며 실제 계좌 우대수수료·최소액·매도 부과금은 미확인이다. [KIS 공개 수수료 안내](https://securities.koreainvestment.com/main/bond/research/_static/TF03ca050000.jsp)를 실제 계좌 명세와 대조해야 한다. 스트레스는 편도 0.30%, 주문별 최소 $0.10, 전체 스프레드 30 bps, 편도 슬리피지 30 bps다. 이 최소액은 확인된 KIS 수수료가 아니다. 정확한 체결명세를 확보하면 고정된 새 시나리오로 사전 등록하고 원본 결과를 보존한다.

`--usdkrw`, `--fx-source`, `--fx-as-of`는 필수다. 환율 이력이 없으면 KRW 결과는 고정환율 환산이며 실제 환손익이 아니다. 선택적 `--fx-history` CSV는 `timestamp,usdkrw` 열을 가지며 각 평가 시각 이전의 최근 값만 사용한다. 최초 데이터 이전 환율이 필요하고, 누락 날짜는 이전 값을 유지하므로 충분히 촘촘하고 일관된 원천을 제공해야 한다. FX 이력이 있으면 각 독립 구간의 8만 원을 구간 시작 시 환율로 달러 환산한다.

실제 데이터·서버·AI 구독/사용 비용은 확인되지 않았다. 값이 없으면 운영비 차감 수익은 빈 값이며 0원으로 단정하지 않는다. 확인한 원화 월 비용은 `--monthly-operations-krw`로 전달한다. 운영비는 거래 손익과 별도 표시하고 관측된 월마다 전액을 차감한다. 첫/마지막 부분 월에도 전액을 차감하므로 보수적 가정이다. 유료 서비스는 추가하지 않는다.

## 실행 명령과 출력

저장소 루트에서 실행한다. 아래 합성 명령의 1,400원은 실제 환율 조회값이 아니다.

```powershell
python scripts/run_exit_experiments.py --synthetic-smoke --output docs/early-exit-audit-20260929/synthetic-smoke-final --usdkrw 1400 --fx-source synthetic-assumption-not-market-rate --fx-as-of 2020-01-01
```

실제 데이터 확보 후의 실행 형식이다. 날짜와 환율·출처는 확보한 데이터로 직접 정한다. 아래 placeholder를 그대로 실행하지 않는다.

```text
python scripts/run_exit_experiments.py --bars PATH_TO_OHLCV.csv --provenance PATH_TO_PROVENANCE.json --output FRESH_OUTPUT_DIRECTORY --usdkrw VERIFIED_START_RATE --fx-source SOURCE_AND_METHOD --fx-as-of ISO_TIMESTAMP --train-end ISO_TIMESTAMP --validation-end ISO_TIMESTAMP
```

필요하면 `--fx-history PATH_TO_FX.csv`, `--monthly-operations-krw VERIFIED_COST`, `--compare-entry-gate`를 추가한다. 전체 데이터는 시간순 train/validation/final로 분리되고 최종 평가 구간 앞의 이력은 지표 준비에만 사용한다. 각 구간의 시작 이전에는 주문하지 않는다. 정책 튜닝 코드는 없다. 후보·설정·구간을 평가 전에 `protocol.json`에 쓰고 SHA-256을 기록한다. 데이터·설정 원본의 hash와 출처는 `manifest.json`에 남는다. 이미 protocol이 있는 폴더는 라이브러리와 CLI 모두 재사용을 거부한다. 재실행에는 새 폴더를 사용하며 기존 결과를 덮어쓰지 않는다. 최종 결과를 보고 동일 최종 구간에 정책을 재맞추면 최종 평가 의미를 잃는다.

| 출력 | 내용 |
|---|---|
| summary.csv | 누적/월중앙값/월 +10% 횟수와 관측 월수/손실 월비율/최악 월/최대낙폭/완결거래/보유기간/승률/손익비/비용/미청산 평가액 |
| monthly.csv | USD 순평가액 수익률, KRW 환산/환율 포함 수익률, 환율 자체 변화, 운영비 차감 평가액 |
| equity.csv | 현금+미실현 보유분을 포함한 매 시점 계좌 평가액 |
| fills.csv | 신호 시각과 체결 시각, 가격·수량·수수료·매도 순손익·이유 |
| reasons.csv | 매도 사유별 실제 모의 매도 체결 수와 순손익 |
| entry_skips.csv | 1주 예산 초과, 현금/비중 부족, 월간 중단 등 진입 거부 |
| order_rejections.csv | 미체결 DAY 주문·동시 위험 초과 등 체결 엔진 거부; 없으면 빈 파일 |
| protocol.json / manifest.json | 사전 고정 설정·후보·데이터 hash·출처·제약 |

`summary.csv`의 월 +10% 횟수, 월중앙값·최악 월·손실 월비율은 USD 기준이다. KRW 월별 성과는 monthly.csv의 별도 열에서 확인한다. 고정 환율에서는 두 수익률이 같다. 외부 입출금은 이 시뮬레이터에 존재하지 않으므로 수익률에 섞이지 않는다. 완결 거래는 종목 잔량이 0이 되는 라운드트립이며 매도 사유별 건수는 부분 매도를 포함한 체결 건수다. 보유기간은 첫 체결부터 완전 청산까지다.

관측 구간의 첫/마지막 월은 부분 월일 수 있다. 월별 observation_start/end를 함께 확인하며 이 월수를 완전한 달력월 표본이라고 주장하지 않는다. 월 +10% 관측 비율은 미래 달성 확률이나 보장 수익률이 아니다. `no_executions`는 전략 검증 불가이며 무손실 우수 전략으로 순위화하지 않는다.

이 엔진은 완성 봉의 종가에서 신호를 내고 다음 봉에서 체결 가능성을 판단한다. 지정가가 봉 범위에 도달하지 않으면 DAY 미체결이다. OHLC의 고가/저가에 닿았다는 사실만으로 실제 호가 대기열/거래량에 따른 체결을 보장할 수 없다. 같은 봉에서 손절·익절을 모두 통과해도 장중 순서를 추정하지 않는다. 보호 판단은 관측 종가에 적용되므로 실제 실시간 손절/익절 체결이라고 부르지 않는다. 장중 고가는 임의로 최고가에 넣지 않는다. 해당 불확실성을 없애려면 시각별 분봉/체결/호가 데이터와 장중 보호 실행 모델이 추가로 필요하다.

합성 smoke는 300개의 생성된 일자·가상 종목 데이터로 5후보 × 2수량방식 × 2위험예산 × 2비용 × 3구간의 120행을 만든다. 주말을 포함한 가상의 시각이며 실제 거래일 이력이 아니다. 일부 조합에서 거래가 없다는 결과도 그대로 보존한다. 이전 `synthetic-smoke` 폴더는 초기 코드 실행의 기록이고 최종 검토용은 `synthetic-smoke-final`이다. 어느 쪽도 과거 시장 수익 증거가 아니다.

모의 운용에서는 진입 신호의 점수·동시 매도 점수, 선택/강제매수 이유, 진입 ATR/초기 손절, 시세 원천/시각, 주문과 체결 연결, 잔량/평균가, 최고가/활성 보호 상태, 재시작 복원, 실제 비용을 기록해야 한다. 충분한 원시 데이터와 실제 계좌 수수료·FX·운영비가 없으면 손절 확대가 순수익 개선인지 손실 확정 지연인지 판단하지 않는다. 실전 적용은 이 증거 검토와 별도의 운용 정책·손실 허용 한도 승인 후에만 검토할 수 있다.
